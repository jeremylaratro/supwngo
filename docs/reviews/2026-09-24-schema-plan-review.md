1. **BLOCKING — Merge semantics are incomplete and order-dependent.** The [precedence table](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:135) has no rule for incoming `asserted`, `derived` versus `measured`, `derived` versus `derived`, or `asserted` versus `asserted`. The especially important collision `existing=measured, incoming=asserted` is undefined. “Incoming measured wins” also lets replaying an older document regress a newer value.  
   **Fix:** Define every pair, distinguish equal-value merges from contradictions, and make resolution deterministic using observation IDs, timestamps/run IDs, and an explicit selected observation. Test associativity, commutativity where intended, and idempotence—not merely the four listed rows.

2. **BLOCKING — “Asserted wins” is a dangerous default.** The justification in [Merge semantics](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:148) conflates scope with authority: a remote assertion and a local measurement describe different environments and should not collide. If they describe the same environment, a typo in hand-authored YAML must not override a fresh measurement while execution continues after a warning.  
   **Fix:** Make contradictory observations unresolved by default and fail consumers that require the fact. Separate `origin: human` from an explicit `pinned/override` decision. Require a deliberate resolution operation or narrowly scoped CLI flag to select the assertion.

3. **BLOCKING — Partial documents turn “unknown” into dangerous false facts.** `ExploitContext` uses confident-looking defaults for protections, architecture, addresses, and runtime profile ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:195)); `Protections` defaults NX/PIE/canary to false ([binary.py](/srv/share/dev/supwngo/supwngo/core/binary.py:61)). A minimal hand-authored document can therefore hydrate an unknown NX state as “NX disabled,” after which `select_technique()` selects shellcode ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:363)).  
   **Fix:** Represent unknown explicitly—tri-state booleans or absent facts—and never serialize dataclass defaults as observations. Consumers must reject, measure, or conservatively handle unknown required values.

4. **BLOCKING — The one-target envelope cannot represent the actual command registry.** The [envelope](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:69) requires one binary target, but `diff` has two binaries ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:1691)), `batch` has N ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:920)), and `source`, `cyclic`, `libc-id`, and `version` have no binary target. `onegadget` targets libc, while `kernel` has a module plus optional kernel artifacts. The example `fuzz-corpus` command does not exist.  
   **Fix:** Either limit conformance to target-bearing commands or replace `target` with typed `subjects` plus roles and per-fact subject references. `batch` should normally emit a manifest and per-binary documents.

5. **BLOCKING — Digest refusal is applied at the wrong boundary.** Refusing merely on `-c` as specified in [the digest guard](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:93) breaks remote exploitation using a local surrogate, patched/rebuilt binaries, debug/release pairs, and commands that do not operate on a binary. Conversely, `--context-mismatch=allow` is too broad: it admits stale absolute addresses along with portable facts. PIE versus non-PIE builds absolutely must not share raw addresses, but architecture, source findings, or user intent might remain usable.  
   **Fix:** Load the document, quarantine incompatible build-bound facts, and refuse only when a consumer attempts to use one. Bind each fact to a subject/build/runtime scope. Provide an explicit rebind/translation workflow rather than a document-wide “allow everything” switch.

6. **BLOCKING — The design creates at least three sources of truth.** The plan serializes `ExploitContext`, stores canonical-looking `facts`, and adds overlapping `blocks`. Existing fields already overlap: `libc.base`, `leaks`, `gadgets`, `attempts`, protections, and both `stack.return_address_offset` and `offset` ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:200), [context.py](/srv/share/dev/supwngo/supwngo/core/context.py:245)). A `libc` or `attempts` block creates another copy. No rule says which value hydrates the next command.  
   **Fix:** Publish an ownership table for every field. Make typed facts the canonical state; hydrate `ExploitContext` solely from them. Blocks should contain report/evidence data and reference fact revision IDs, not repeat authoritative values.

7. **BLOCKING — Reading a document does not make commands consume it.** `exploit` always creates a fresh context ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:256)); the canonical engine does the same ([orchestrator.py](/srv/share/dev/supwngo/supwngo/exploit/pipeline/orchestrator.py:99)). Its only resume interface accepts `offset`, `canary_value`, `libc_base`, and `pie_base` ([orchestrator.py](/srv/share/dev/supwngo/supwngo/exploit/pipeline/orchestrator.py:129)), not the proposed `stack.return_offset`, and applies them after profiling and leak acquisition. The plan also omits precedence between CLI flags such as `--offset`/`--libc` and loaded facts.  
   **Fix:** Add a typed fact-to-consumer binding layer and inject the hydrated context before any analysis runs. Define command capability metadata and explicit precedence among CLI input, context observations, and new measurements.

8. **BLOCKING — A shared Click decorator cannot capture current command results.** There are 31 callbacks, most returning `None`; their useful objects live in local variables and output is written or printed inside branches. Examples include `analyze`’s unconditional legacy file write ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:115)), `source`’s conditional writes ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:1209)), and early returns in `exploit`, `onegadget`, and `solve`. A wrapper cannot recover `static_results`, `report`, `engine.context`, or partial failures after the callback returns.  
   **Fix:** Refactor callbacks to return a common `CommandResult` containing subjects, facts, blocks, and artifacts, or explicitly publish to a context sink. Budget real per-command integration work; this is not a mechanical decorator-only change.

9. **MAJOR — The byte-identical round-trip requirement is impossible as designed.** The [test requirement](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:185) routes the whole document through `ExploitContext`, which cannot retain history, provenance, conflicts, blocks, artifacts, unknown extension fields, or original key ordering. Updating `updated` also contradicts byte identity.  
   **Fix:** Introduce a `ContextDocument` aggregate that preserves the envelope and projects a subset into `ExploitContext`. Test semantic/canonical JSON equality; reserve byte identity for parse-and-write with no mutation.

10. **MAJOR — Existing `to_dict()` producers are lossy and cannot serve as reversible adapters.** `AddressReport` converts addresses to hex strings and writable regions to display strings ([addresses.py](/srv/share/dev/supwngo/supwngo/analysis/addresses.py:102)); `OffsetResult` omits `stack_data` and `pattern_found` ([offset_finder.py](/srv/share/dev/supwngo/supwngo/exploit/offset_finder.py:53)); `AttemptRecord` stores only payload length and stringifies complex artifacts ([contracts.py](/srv/share/dev/supwngo/supwngo/exploit/pipeline/contracts.py:96)). `ExploitContext` itself contains bytes, sets, enums, tuples, and `Any` values.  
    **Fix:** Define field-specific lossless codecs and one canonical address representation. Treat existing serializers as presentation/report sources only; do not claim their blocks can reconstruct state.

11. **MAJOR — Provenance categories conflate unrelated dimensions.** `measured`, `derived`, `assumed`, and `asserted` mix acquisition method, epistemic status, and authorship. A human can report a measurement; a tool can assert a default. “Human wrote it” also cannot be inferred or authenticated from a YAML file.  
    **Fix:** Split provenance into fields such as `origin`, `acquisition`, `authority`, `confidence`, and `scope`. Give each observation a stable ID and reserve explicit override state for policy rather than provenance.

12. **MAJOR — Derived and runtime facts have no dependency or validity model.** A libc base derived from a leak remains selected when the leak is superseded. ASLR bases, canaries, heap addresses, verification receipts, and prompts are process/session-specific, but the schema only binds them to the binary and timestamp. Retaining the old fact in `superseded[]` does not invalidate dependents.  
    **Fix:** Add `derived_from` revision IDs, run/session/process scope, environment identity, and validity/expiration. Recompute or invalidate dependent facts whenever an input revision changes.

13. **MAJOR — Accumulation is specified only for scalar facts.** No merge policy exists for `blocks`, artifacts, history, crashes, attempts, gadgets, or symbol collections. “One block per domain” implies a second run overwrites the first; concatenation would instead create duplicate attempts and unbounded growth.  
    **Fix:** Give every block a schema version, run ID, identity key, and explicit replace/append/set-union policy. Attach facts and artifacts to the history event that produced them and define compaction.

14. **MAJOR — The output compatibility story is contradictory.** Dedicated `--context-out` can be additive without changing `--json` or current `-o` files, yet the plan declares a breaking output-shape change and proposes `--legacy-json` ([plan](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:202)). It never states which outputs are actually replaced.  
    **Fix:** For v1, leave existing outputs untouched and make `--context-out` exclusively emit the new document. If replacement is intentional, enumerate every affected command/output and version that migration independently.

15. **MAJOR — The layering constraint conflicts with deserialization.** `core/context.py` deliberately avoids runtime imports from `exploit` ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:16)), while attempts and verification levels are stored as `Any`. Reconstructing typed `AttemptRecord` and `VerificationLevel` inside `ExploitContext.from_context_doc()` either violates that direction or produces untyped dictionaries that existing consumers will not accept.  
    **Fix:** Put document mapping in a higher-level module that may depend on both `core` and `exploit`, or use an injected codec registry. Keep `core.context` free of schema adapters for higher layers.

16. **MAJOR — The proposed conformance sweep is not executable as a generic registry test.** Commands require incompatible fixtures and external systems: AFL campaigns, GDB, angr, decompilers, libc databases, kernel inputs, interactive workflows, and one- or multi-target arguments. Validating output alone also does not prove that another command consumes it.  
    **Fix:** Maintain a command capability registry with target cardinality, fixture factory, producer adapter, and consumed fact keys. Unit-test every adapter, then add focused cross-command tests such as `analyze → pwn`, `offset → autopwn`, and remote/local mismatch cases.

17. **MAJOR — Persistence, trust, and privacy are omitted.** In-place read/merge/write needs atomic replacement and locking or concurrent commands will lose updates or truncate the document. Artifact paths and YAML are untrusted inputs; paths need defined relativity, digest verification, and traversal protection. The document may also contain flags, payloads, remote endpoints, absolute paths, commands, and argv-derived data.  
    **Fix:** Specify atomic writes, locking/conflict detection, safe YAML loading, artifact sandboxing, path semantics, restrictive default permissions, and redaction rules. Define schema-version migration and forward-compatibility behavior as well.

18. **MINOR — `target.type` is not a valid exclusive classification.** `exec|dyn|static` mixes ELF type (`ET_EXEC`/`ET_DYN`) with linkage; static PIE can be both dynamic-type and statically linked.  
    **Fix:** Split this into fields such as `format`, `object_type`, and `linkage`.

**Verdict: REJECT.** The target model, merge policy, canonical ownership, and command consumption contract need redesign before implementation; otherwise the schema will standardize contradictory and unsafe state rather than eliminate it.
