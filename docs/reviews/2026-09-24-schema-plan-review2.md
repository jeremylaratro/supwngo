1. **BLOCKING — `asserted` is provenance, not authority; “asserted wins” is unsafe.** A typo, stale hand-authored address, or malicious document would override a fresh measurement and then feed exploit generation. Merely warning does not protect non-interactive consumers. The table is also asymmetric: it omits existing `measured` + incoming `asserted`, plus `derived` combinations and `asserted` + `asserted`, making results dependent on merge order. “Same key but different scope”—for example, local versus remote `libc.base`—is another unhandled collision.  
   **Fix:** keep observations append-only and separate provenance from selection authority. Scope every observation, mark contradictory same-scope values unresolved, and refuse to consume safety-critical unresolved facts. Require an explicit pin/resolution action to prefer an assertion. Specify the complete matrix and test commutativity, associativity, and idempotence. See the incomplete table at [the plan](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:135).

2. **BLOCKING — SHA equality does not make runtime facts reusable.** PIE/libc/heap bases, canaries, leaked stack addresses, and process state can change between invocations while `target.sha256` remains identical. The current design therefore strongly validates static identity while allowing the most dangerous stale values through.  
   **Fix:** classify facts by lifetime and scope: `build`, `environment`, `endpoint`, `process/session`, and `attempt`. Persist offsets and static properties freely, but require a matching runtime/session identity—or explicit remeasurement—before hydrating absolute bases, canaries, heap state, or leaks.

3. **BLOCKING — A singular `target.sha256` mishandles remote, rebuilt, and multi-target work.** Remote exploitation commonly uses a local surrogate whose bytes may differ from the deployed binary; patched/relinked binaries invalidate some facts but not necessarily source-level findings. A blanket `--context-mismatch=allow` disables protection for every fact, including absolute addresses. The model also cannot naturally represent `diff`’s two binaries, `batch`’s many binaries, or libc/module/source-only commands; those command shapes are visible in [cli.py](/srv/share/dev/supwngo/supwngo/cli.py:1691) and [cli.py](/srv/share/dev/supwngo/supwngo/cli.py:920).  
   **Fix:** replace `target` with identified `subjects` and explicit roles such as `local_binary`, `remote_deployment`, `libc`, `kernel`, and `old/new_binary`. Bind each fact/block to a subject. On mismatch, import only facts declared build-independent or successfully rebased/revalidated; never offer a single unrestricted `allow`.

4. **BLOCKING — The design creates at least three sources of truth.** `facts`, domain `blocks`, and serialized `ExploitContext` all overlap on protections, gadgets, leaks, libc base/offsets, crashes, attempts, and stack offset. The existing model already has duplicate representations: `offset` versus `stack.return_address_offset` in [context.py](/srv/share/dev/supwngo/supwngo/core/context.py:245), and libc base versus named leaks as consumed in [handoff.py](/srv/share/dev/supwngo/supwngo/exploit/pipeline/handoff.py:200). Adding `blocks.libc`, `blocks.leaks`, and `blocks.attempts` compounds this.  
   **Fix:** make normalized `facts` the sole canonical consumable state. Blocks should be immutable producer reports/evidence that reference fact IDs, not competing values. `ExploitContext` should be a one-way runtime projection of selected facts; writing it back must not independently overwrite facts or blocks. Define an explicit mapping and validate invariants.

5. **BLOCKING — “Not a new state object” contradicts lossless round-tripping.** `ExploitContext` has nowhere to retain provenance, conflicts, superseded observations, history, arbitrary blocks, artifacts, or unknown future fields. Consequently, the proposed `doc → ExploitContext → doc` byte-identical test cannot pass without hiding the original document inside `ExploitContext`; timestamps and canonicalization also make byte identity inappropriate. See [the non-goal](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:22) and [the test](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:185).  
   **Fix:** introduce a `ContextDocument` model that owns the complete document and exposes `to_exploit_context()`/`apply_exploit_context_delta()`. Test semantic canonical equality and preservation of unknown fields, not raw bytes across a lossy runtime projection.

6. **MAJOR — A shared Click decorator cannot perform the claimed command integration.** It can add flags, load a document, and write history, but command results live in local variables and most handlers return `None`. It cannot extract learned facts from `gadgets`, reports, engines, or early-return paths. The 29 commands are heterogeneous: some target binaries, some libc/source/kernel inputs, some no artifact at all, and some run indefinitely. For example, `onegadget` returns early before producing a result at [cli.py](/srv/share/dev/supwngo/supwngo/cli.py:842), while `autopwn` owns its context inside the function at [cli.py](/srv/share/dev/supwngo/supwngo/cli.py:2493).  
   **Fix:** define a command capability/adapter registry with target resolver, context importer, result exporter, and completion policy. Refactor handlers to return a structured `CommandResult` or explicitly publish deltas. The decorator should only orchestrate that protocol. Re-estimate “all commands up front” as a substantive refactor, not mechanical decoration.

7. **MAJOR — Input precedence is unspecified.** The plan defines fact-to-fact merging but not context versus explicit CLI arguments, CLI defaults, environment detection, or new measurements. For example, `--offset`, `--libc`, and `--remote` can conflict with loaded context, and Click defaults must not silently overwrite context.  
   **Fix:** publish a separate input-resolution table. Use Click’s parameter-source information to distinguish explicit arguments from defaults. A reasonable order is explicit invocation override/pin, resolved context fact, then command default; measurements should create observations and conflicts rather than silently replace explicit inputs.

8. **MAJOR — Update transactions and concurrent writers are omitted.** `-c ctx.json --context-out ctx.json`, interrupted long-running commands, and two processes updating one document can truncate data or lose one writer’s facts. “Accumulate, not clobber” cannot be guaranteed by the merge function alone.  
   **Fix:** use a revision/generation field, advisory locking or compare-and-swap, and atomic temp-file + fsync + rename writes. Record command outcome (`success`, `partial`, `failed`, `interrupted`) and define which deltas are committed on each outcome.

9. **MAJOR — The conformance test checks shape, not interoperability.** Invoking every command is impractical: fuzzing, symbolic execution, external decompilers, kernel analysis, and remote-libc lookup require different fixtures, dependencies, and time budgets. A document can validate while no downstream command actually consumes its facts.  
   **Fix:** split testing into fast registry coverage, adapter unit tests, producer→consumer contract tests for each shared fact, mismatch/scope tests, and a small end-to-end core matrix. Add unknown-field preservation, malformed/oversized YAML, atomic-write failure, concurrency, and stale-runtime-fact tests.

10. **MAJOR — Untrusted context handling lacks a threat model.** A hand-authored document can contain local paths, artifact references, command text, enormous YAML aliases, and sensitive values. Hydrating `LibcInfo.path` currently performs file analysis during initialization in [context.py](/srv/share/dev/supwngo/supwngo/core/context.py:83), so deserialization must not blindly instantiate side-effecting models. Contexts may also expose flags, canaries, ASLR addresses, endpoint details, and filesystem paths.  
    **Fix:** deserialize into inert schema objects; never execute recorded commands; use safe YAML with size/depth/alias limits; validate artifact digests before opening paths; require explicit permission for external paths; write private files with restrictive permissions; and provide redaction/export modes.

11. **MAJOR — The claimed breaking JSON change is unnecessary and internally inconsistent.** Dedicated `--context-out` can coexist with existing `--json` and `-o` formats, while the plan also says existing `to_dict()` serializers remain intact. Changing current output shapes and adding `--legacy-json` multiplies the migration burden without advancing context interchange.  
    **Fix:** leave existing outputs unchanged in v1. Make the context document available only through `--context-out`, or an explicit `--json-format=context`. Deprecate legacy formats separately after real adoption.

12. **MINOR — “Portable” conflicts with absolute paths and mutable artifact references.** An absolute `target.path` and artifact paths cease to work when the document is moved, even if their digests remain valid.  
    **Fix:** treat paths as optional hints, make content identity primary, support paths relative to the context file, and define missing-artifact behavior plus digest verification.

13. **MINOR — Canonical values and schema evolution need tighter rules.** The plan does not define null versus unknown versus zero, address representation, confidence bounds, timestamp normalization, extension fields, or v1 migration behavior. Current code uses both zero and `None` as absence, which will produce ambiguous documents.  
    **Fix:** use `null` consistently for unknown values, specify unsigned ranges and address-space/module metadata, constrain confidence to `[0,1]`, normalize timestamps to UTC, reserve extension namespaces, and define unknown-version/unknown-field policy.

**REJECT**
