
# Dimension D3 — Exploitation, the owner's PASS criteria, and the next sprint (adversarial)

Your dimension: does supwngo get a user from "binary" to "the right method + a working (or
completable) exploit", and is the team's next sprint aimed at the right thing? Scope:
- **The PASS criteria** (`_review/BRIEF.md` §2) and the orchestrator's interpretations. Challenge both:
  are they the right bar, are they measurable, what is missing (e.g. "right method" without a
  correct offset is useless; is "template that works with manual inputs" testable without a human?).
  Propose an exact, automatable scoring rubric per target × criterion.
- **The scorecard** (`_review/SCORECARD.md`): 7 targets × {pwn, template, decompile, offset}, measured
  today. Read the per-target evidence and say which failures share a root cause.
- **Method selection.** `supwngo/exploit/strategy.py` (StrategySuggester: gates, `WIN_FUNCTIONS`,
  confidence/priority ordering), `template` (`supwngo/cli.py`, the `-t auto` path and the payload
  generators it calls), the canonical pipeline's technique executors under
  `supwngo/exploit/pipeline/executors/` (e.g. `srop_nowrite_techniques.py`), the legacy
  `exploit --auto` engine. Why do they disagree; which one should own "the method"?
- **User-supplied components.** No `--winfun` / `--eip` exists. Design the flag surface and how a
  supplied value (symbol name or address; return target; known offset; leak) flows into method
  selection and into the emitted template, so "works with a provided component" is true end to end.
- **Offsets.** `supwngo/exploit/offset_finder.py` (GDB → core dump → binary search cascade; the
  binary-search path crashes with `TimeoutExpired` on sick_rop and returns only an approximate crash
  threshold). Design **static** offset inference (buffer base from the frame/`lea`/`sub rsp` →
  saved-RIP distance, canary-aware, works on stripped/no-`main`/PE binaries) and say how to validate
  it against the dynamic result where the target can run.
- **Templates.** Are emitted templates correct, runnable, and honest about the manual inputs they need
  (placeholders, asserts, comments)? How would you test "a template that works with manual inputs"
  automatically (e.g. fill placeholders from ground truth and run against the local binary)?
- **The S6 plan draft** (`_review/S6-PLAN-DRAFT.md`, covering RT-08 SROP gate, RT-09 custom-allocator
  heap detection, RT-10 `report` findings). Is it the right next sprint given the PASS criteria? What
  should be added, cut, split or re-ordered? Critique its designs (regexes, gates, test strategy).
- Heap / integer / UAF targets (auth-or-out, sabotage, bon-nie-appetit): what is a realistic PASS for
  these under the owner's criteria, and what is the cheapest path to it?
Use `D3` as the ID prefix.
