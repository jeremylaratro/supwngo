### 0. Verdict

- **supwngo is six fact models and five deciders sharing one repo, not one tool.** The canonical pipeline is the best-engineered part, but `pwn`, `template` and `batch` — the commands the PASS criteria are measured on — never consult it. They ask a 1,004-line heuristic that knows about 12 approaches while the pipeline registers 40 executors.
- **Method selection is not derived from vulnerability facts anywhere.** `StrategySuggester` ranks from protections, gadgets and imports; the pipeline orders by a hand-curated list tuned on the benchmark corpus; `explain` uses per-family hard-coded scores. The `vulns/` detectors feed none of them.
- **Nothing is cached, so nothing scales.** Each angr op rebuilds `CFGFast` in a fresh process, each Ghidra call re-imports the binary into a throwaway project, and 28 files shell out to `objdump` independently. `core/database.py` (the "cache") has no production caller.
- **The brief is wrong on two points that change the roadmap.** `--win` / `--ret2` / `--rop` already exist (`cli.py:66-109`), but only on `solve`/`autopwn`/`explain`. A CI workflow also exists (`.github/workflows/ci.yml`).
- **Highest-leverage move:** build one content-addressed per-binary knowledge base (typed facts with provenance, produced by cached analyzers, with operator overrides stored as asserted facts) and one planner over it. Make `pwn`, `template`, `explain` and `autopwn` four renderers of the same plan, then delete what no longer has a caller.

I could not run anything. Line counts come from grep; everything marked UNVERIFIED is inference.

### 1. Findings

**D1-F1 — Five deciders with no shared source of truth (critical).**
- `pwn` and `batch` call `StrategySuggester` directly (`cli.py:866-870`, `cli.py:1134-1135`).
- `template -t auto` calls `StrategySuggester`, then squeezes the result through a five-entry map whose default is `"ret2system"` (`cli.py:1224-1231`). It then generates through the legacy `AutoExploiter` (`cli.py:1212`, `exploit/auto.py:2758-2759`), which has its own fallback chain (`auto.py:2765-2773`).
- `autopwn`/`solve` use FIRST_TECHNIQUES, then the suggester via a nine-entry `APPROACH_TO_TECHNIQUE`, then registration order (`orchestrator.py:56-71`, `1099-1140`). On failure they fall through to `EnhancedAutoExploiter` in the CLI layer (`cli.py:2953`, `3565`).
- `exploit --auto` chains three legacy engines inline (`cli.py:370`, `413`, `436`, `457`).
- `explain` picks by `max(route.score)` over 16 families (`walkthrough/registry.py:152`).
- Why it matters: the measured `template` picking ret2system for a static binary is a structural consequence of that default. A fix in one engine cannot reach the others.

**D1-F2 — "Right method" is computed without knowing the bug (critical).**
- `StrategySuggester.analyze()` reads protections, gadgets, the import table and a name list (`strategy.py:206-291`). `VARIABLE_OVERWRITE` is appended unconditionally (`strategy.py:272`).
- No file under `exploit/pipeline/` or `strategy.py` imports a `vulns` detector, except one canary-bypass import (`executors/heap_and_bypass.py:105`). Only `report` runs them (`reporting/adapter.py:62-66`, `cli.py:3771`).
- Detection has moved into each executor's `is_applicable()`, where it is invisible to `pwn` and `report`. That explains `report` returning 0 findings on binaries the pipeline has gates for.
- Why it matters: the owner's primary criterion is "output the right method". The architecture has no place where bug class → primitive → method is represented.

**D1-F3 — Six incompatible fact models; stringly-typed facts are already producing wrong answers (high).**
- The models are: `Binary`/`Protections`; `ExploitContext` with flat `profile_*` fields (`context.py:306-314`); `StrategyReport`; walkthrough `TargetFacts` with its own `Confidence`/`Evidence` (`walkthrough/facts.py:135`); `vulns.Vulnerability`; and `schema/resolve.py`'s `FactStore`.
- RELRO is produced as `"Full RELRO"` / `"Partial RELRO"` / `"No RELRO"` (`binary.py:381-391`). Consumers compare it to `"full"` (`strategy.py:454`, `976`), `"Full"` (`vulns/leak_finder.py:329`, `analysis/imports.py:499`, `exploit/pie_bypass.py:191`) and `"none"`/`"partial"` (`exploit/chainer.py:299`).
- So `_check_ret2dlresolve_viable` can never reject on Full RELRO, and `pwn` will list ret2dlresolve for rocket_blaster_xxx, sabotage and bon-nie-appetit (UNVERIFIED by execution; the code path is unambiguous).
- Fortify detection is `"_chk" in str(self.symbols.keys())` (`binary.py:369`).
- Win-function detection exists in at least seven separate lists (`strategy.py:178`, `pipeline/profile_stage.py:30`, `auto.py:168`, `enhanced_auto.py:111`, `offset_finder.py:881`, `objptr_hijack_techniques.py:852`, `chainer.py:323`). The orchestrator already has to patch the report after the fact to stop two of them disagreeing (`orchestrator.py:1081-1094`).

**D1-F4 — The single-source-of-truth facts layer was built, then orphaned (high).**
- `supwngo/schema/` (3.7k LoC) implements provenance, scope, partial-order merge, pin and retract, with property tests. Only tests and its own mutant file import it.
- The audit confirms: "standardized-context-schema | SUPERSEDED | Only unit 1 shipped" (`docs/reports/2026-11-11-outstanding-work-audit.md:53`).
- Four review rounds went into merge semantics before a single producer or consumer existed. The process optimised rigour on the wrong unit.
- Either wire a thin subset or delete it. Do not let it sit as apparent infrastructure.

**D1-F5 — Operator overrides exist but only on one engine (high; corrects the brief).**
- `--win` / `--ret2` / `--rop` are attached to `solve`, `autopwn` and `explain` (`cli.py:66-109`) and resolved in the engine constructor (`orchestrator.py:706-747`).
- `pwn`, `template` and `offset` accept none of them. `template` has only `--offset` (`cli.py:1190`).
- PASS criterion (a) is therefore partially met in one engine and unmeasured, because the scorecard exercises the other.

**D1-F6 — No analysis is cached or shared (high).**
- `_op_cfg`, `_op_static_functions`, `_op_dataflow`, `_op_strings_xrefs` and `_op_decompile` each build a new `angr.Project` and `CFGFast` (`_angr_subprocess.py:88-89`, `147-148`, `166-167`, `191-192`, `225-226`).
- Ghidra runs `-import … -deleteProject` in a `TemporaryDirectory` on every call (`decompile.py:358-371`). `decompile_all` would therefore run one full auto-analysis per function, up to 100 (`decompile.py:609-612`).
- `GadgetFinder(` is constructed at 24 sites, and twice per `autopwn` run (`profile_stage.py:70`, `orchestrator.py:1074`).
- `Database` is exported but never instantiated outside tests (`core/__init__.py:5`; `tests/test_core.py:111`).
- Why it matters: an LLM agent driving the CLI through a shell issues many commands per binary, and each pays the full cold cost. The 180 s Ghidra cap is being spent on re-analysis.

**D1-F7 — Technique ordering is a hand-tuned, corpus-fitted list (high).**
- FIRST_TECHNIQUES spans `orchestrator.py:101-537`: about 440 lines of prose justifying seats by timings on `benchmark/corpus_*`.
- The comments record pairwise interference (`:333-351`), seats that tax neighbours (`:487-514`), and one executor's 72.9 s cost shaping four other seats (`:364-366`, `387-392`, `430-433`).
- The loop is serial with no global deadline. The only overall bound is an external SIGTERM (`cli.py:2891-2926`), and controls run to "316.6 s" (`orchestrator.py:189`).
- Why it matters: this is O(n²) maintenance and overfitting by construction. HTB solves stayed at 0/7 while each in-house family reached 5/5.

**D1-F8 — Executors are 1–3k-line silos with almost no shared substrate (high).**
- 40 executors are registered (`executors/__init__.py:120-161`); the architecture doc still says 11.
- `_shared.py` is 256 lines. The executor files run from 142 to 3,334 lines (`objptr_hijack_techniques.py`), with a typical file near 1,100.
- Each re-implements disassembly scraping, menu probing and script emission. Twelve call `Binary.load` themselves.
- Walkthrough families import executor internals module by module (`walkthrough/families/heap_strlen.py:58`, `fini_array.py:97` and others), then add 700–3,766 lines each (`families/integer.py`).
- A new bug class costs roughly 1–3k lines of executor, 1–3k of walkthrough, a seat negotiation and a corpus. That price is why the tree is 102k LoC.

**D1-F9 — No format or architecture abstraction; PE has nowhere to plug in (high).**
- `Binary.load` is hard-wired to pwntools `ELF` plus pyelftools (`binary.py:186-190`), and `os` defaults to `"linux"` (`binary.py:122`).
- `batch` filters on the `\x7fELF` magic (`cli.py:1120`). Gadget specs are x86-64 register names (`walkthrough/facts.py:47-55`, `profile_stage.py:77`).
- `lief` is a declared dependency with a `_lief_binary` field (`binary.py:126`), but I found no `import lief` anywhere.
- `decompile` defaults to `main` (`cli.py:2070-2071`), which fails on two of the seven targets.
- There are at least nine separate dynamic offset finders (`offset_finder.py:191`, `_shared.py:54`, `delivery.py:225`, `walkthrough/facts.py:865`, `auto.py:382`, `enhanced_auto.py:700`, `vulns/stack_bof.py:236`, `analysis/dynamic.py:539`, `fmtstr_probe.py:848`). None is static, so "offset on all" including PE is unreachable from the current design.

**D1-F10 — Dead and legacy weight (medium).**
- My grep finds no importer other than `exploit/__init__.py` for: `brop`, `ld_preload`, `reliability`, `payload_synthesis`, `pie_bypass`, `libc_auto`, `got_plt`, `bypass`, `primitives`, `seccomp_advanced`, `signal_handler`, the restricted and constrained shellcode modules, and `advanced_bypass/` (CFI/CET/MTE/PAC, about 3.2k lines).
- The audit adds "11 `exploit.heap` modules are not registered as pipeline techniques".
- `exploit/__init__.py:3-200` and `supwngo/__init__.py:23-61` import all of it eagerly, so `supwngo --version` loads the whole graph (startup cost UNVERIFIED).
- `auto.py` (2,907 lines) and `enhanced_auto.py` (1,432) measured 0/7 yet remain the default fallback and the generator behind `template`.

**D1-F11 — Concurrency is safe only inside the harnesses (medium).**
- ADR-001 states "Non-test processes are not covered". `benchmark/run_bench.py:167` patched itself, but the product has no run-isolation layer.
- Any external parallel driver shares the pwntools gadget cache, whose torn reads become silently wrong results.
- `batch` is a serial in-process loop with no per-target timeout or isolation, and it skips gadget analysis entirely (`cli.py:1127-1135`).
- The harnesses use thread pools around subprocesses (`run_bench.py:1218`, `scripts/retest_matrix.py:141`). That is adequate for one host, but there is no sharding, resume or cluster story.

**D1-F12 — Error handling hides degradation (medium).**
- There are 617 broad `except Exception` sites across 135 files.
- The canonical failure pattern, per ADR-001, is "plausible, actionable, wrong answer". The legacy fallback is wrapped in `except Exception: pass` (`cli.py:2967-2968`).
- `analysis_backend` / `angr_budget_exceeded` is the right idea, but it is applied per command by hand.

**D1-F13 — Packaging, CI and test architecture (medium).**
- `setup.py` duplicates `pyproject.toml` and has already drifted (no `pytest-timeout`, `setup.py:54-61`).
- `requirements.txt:40` references `supwngo/ai/*`, which was deleted. `sqlalchemy`, `networkx`, `pyyaml` and `unicorn` are hard dependencies with no import I could find.
- `requires-python >=3.8` is claimed, but CI lists 3.10–3.12.
- The `Dockerfile` copies neither `README.md` nor `LICENSE`, both referenced by `pyproject.toml:9-10`, and installs no Ghidra or JDK. The image likely fails to build (UNVERIFIED).
- CI runs `pytest tests/ -q -x` with a 20-minute cap and no corpus build or Ghidra. If it runs at all, it exercises the skippable subset.
- Tests are a flat directory of 92 files with one `slow` marker. Several are named after history (`test_new_modules.py`, `test_phase_modules.py`), and some cover modules from F10.

**D1-F14 — Planning documents: where they are right, stale or wrong (medium).**
- **Right:** the 09-23 pipeline doc's contracts (`AttemptRecord`, `VerificationReceipt`, the executor ABC), its import-layering rule, and the idea in ADR-001 of isolating rather than patching.
- **Stale:** the same doc says 11 executors, `leak_stage` is a no-op, and legacy retirement is "a later phase". All of `docs/roadmaps/` except PARKED is obsolete by the audit's own account. PARKED still lists `windows/`, `ai/`, `api/` and `distributed/`, none of which exist in this tree, and parks Windows, which the owner has just un-parked.
- **Wrong:** folding pipeline state flat onto `ExploitContext` because of an import cycle (doc §8). The cycle is caused by `exploit/__init__.py`'s eager imports, not by the data model.
- **Wrong:** rejecting the A-1 modularity assessment with no successor. Its evidence (8 files for one capability) describes the real problem.
- 141 docs for 143k LoC with stale `Status:` headers means the plan corpus is itself unmaintained.

### 2. Recommendations

**D1-R1 — Per-binary knowledge base with a cached analyzer runner.**
- Add a `supwngo/kb/` package holding a `TargetKB` keyed by sha256, stored at `~/.cache/supwngo/<sha256>/` as JSON artefacts.
- Facts are typed (enums for RELRO, arch, format) and carry `{value, provenance, producer, producer_version, evidence}`. Keep only the `Provenance` vocabulary from `schema/resolve.py`.
- Analyzers are registered classes declaring `provides`, `requires`, `budget_s` and `version`. The runner executes each in a killable subprocess (generalise `_angr_subprocess.run_angr_op`), writes atomically, and records `degraded` or `timed_out` as a fact.
- The first three analyzers are `loader`, `ghidra_export` (D1-R3) and `gadgets`.
- Operator inputs (`--win`, `--ret2`, `--offset`, `--libc`) are written as `asserted` facts, so every command honours them.
- Add `supwngo facts <bin> --json` as the agent-facing surface.
- **Impact:** removes F3, F5, F6 and F11 at the root. **Effort:** M. **Dependencies:** none. **Risk:** becoming schema-v5 bikeshedding; cap the first version at 25 fact keys with no merge algebra.
- **Success measure:** on the 7 HTB targets plus `benchmark/corpus`, a second invocation of any analysis command completes in ≤ 20% of the cold wall time, and a test asserts zero raw-string RELRO comparisons remain.

**D1-R2 — One planner; four commands become renderers.**
- Add `supwngo/plan/`. Detectors emit `Hypothesis{bug_class, site, primitive, evidence, confidence}` into the KB.
- Each technique gets a declarative `TechniqueSpec{name, requires_primitive, requires_facts, blocked_by, cost_class}` beside its executor. `Planner.rank(kb)` returns ordered `PlanStep`s with missing facts enumerated.
- `pwn` prints the plan, `template` renders it with named holes for the missing facts, `explain` narrates it, and `autopwn` executes it.
- Delete `APPROACH_TO_TECHNIQUE`, the `tech_map` at `cli.py:1224`, and eventually FIRST_TECHNIQUES.
- Migrate incrementally: derive each `TechniqueSpec` from the existing `is_applicable()` first, and treat the current ordering as a prior.
- **Impact:** directly targets the PASS criteria (right method, listed and recommended) and ends F1 and F2. **Effort:** L, with a first slice of M covering the stack-BOF family (ret2win, ROP, SROP, ret2libc), which is 4 of the 7 targets. **Dependencies:** D1-R1; detector depth from the vulnerability-discovery dimension. **Risk:** planner regressions on the in-house corpora; gate on per-target non-regression with `run_bench.py`.
- **Success measure:** the cross-command agreement rate (`pwn` recommended = `template` technique = `explain` family = `autopwn` first attempted) is 100% by construction on all corpus binaries, and "right method listed" is ≥ 6/7 on HTB.

**D1-R3 — One Ghidra pass per binary, exported and cached.**
- Extend the committed Java script to emit one JSON for the whole program: functions, pseudo-C, stack-frame variables with offsets, call graph, string cross-references and imports.
- Run it once as the `ghidra_export` analyzer and keep the Ghidra project in the cache.
- `decompile -f X`, static offset inference (buffer variable offset to the return slot, canary-aware), win-function discovery through cross-references from `flag.txt` or `/bin/sh` to the containing function, and in-binary allocator recognition all become KB lookups.
- This is the path to "offset on all" and to PE support, since Ghidra loads PE natively and nothing has to execute.
- **Impact:** unlocks three PASS criteria at once and removes most angr use from the hot path. **Effort:** M. **Dependencies:** D1-R1, and the root cause of the 180 s cap being understood. **Risk:** Ghidra frame recovery is wrong on hand-written assembly such as sick_rop; keep a capstone prologue fallback and label the provenance.
- **Success measure:** a static offset is reported for ≥ 5/7 HTB targets and for 100% of mingw PE fixtures with a known ground-truth offset; `decompile` returns non-empty pseudo-C for 7/7, including the two with no `main`; a warm `decompile` takes under 2 s.

**D1-R4 — Image abstraction for format and architecture.**
- Define an `Image` protocol (segments, symbols, imports, entry, arch, protections) with `ElfImage` (the current code) and `PeImage` (lief, already a dependency).
- Add an `ArchSpec` (register names, calling convention, syscall convention) to replace literal `rdi`/`rax` tables.
- Scope PE to load, protections, decompile and offset. Exploitation code must reject non-ELF explicitly instead of crashing.
- **Impact:** makes the "exe" criterion real. **Effort:** M. **Dependencies:** D1-R1; D1-R3 for most of the value. **Risk:** PE scope creep into exploitation.
- **Success measure:** `checksec`, `decompile` and `offset` succeed on 100% of the x64 and x86 mingw fixtures, and 0 commands produce a traceback on PE input.

**D1-R5 — Delete on a schedule, with a reachability gate.**
- Remove the legacy fallback default (owner decision D-1). Port `template` onto the planner, then delete `auto.py`, `enhanced_auto.py`, `generator.py`, `chainer.py` and every module in F10 with no CLI path.
- Empty `exploit/__init__.py` and `supwngo/__init__.py` of eager imports.
- Add a CI test that fails if any module under `supwngo/` is unreachable from a CLI command or a registry.
- **Impact:** an estimated 25–35k LoC gone, faster startup, and an honest test count. **Effort:** M. **Dependencies:** D1-R2 for `template`. **Risk:** low, since the legacy engine measures 0/7.
- **Success measure:** `supwngo/exploit/` is ≤ 70k LoC, `supwngo --version` takes under 0.5 s cold, and the reachability test is green.

**D1-R6 — Shared executor substrate.**
- Extract a `Disasm` service (one cached objdump or capstone pass in the KB), a `MenuModel` (the prompt and menu discovery now re-implemented per heap executor), and a single `ScriptBuilder`.
- Executors shrink to a gate, a payload and a verify step. Walkthrough families consume the same `TechniqueSpec` and evidence rather than importing executor modules.
- **Impact:** cuts the marginal cost of a new bug class by an estimated factor of 3–5. **Effort:** L, done incrementally with the three largest files first. **Dependencies:** D1-R1, D1-R2. **Risk:** regressions; gate each step with `measure_family.py`.
- **Success measure:** the next new technique lands in ≤ 400 lines including its walkthrough, and the count of `objdump` call sites falls from 28 files to 1.

**D1-R7 — Corpus runner as a product feature.**
- Add `supwngo corpus run <manifest> --jobs N --shard i/n --budget S --out DIR`.
- Run one subprocess per target-command pair, each with its own process group, `TMPDIR`, `XDG_CACHE_HOME`, rlimits and a hard global deadline. Give the orchestrator loop an internal deadline too.
- Output is JSONL, resumable, with a deterministic seed and a recorded load average. `batch`, `retest_matrix.py`, `coverage_sweep.py` and `htb_rescore.py` collapse into it.
- Cluster use is `--shard` over ssh across the four Spark nodes, with the KB cache rsynced or on a shared mount. Do not build a scheduler.
- **Impact:** makes scorecards cheap and comparable, which is a precondition for every measured claim in the roadmap. **Effort:** M. **Dependencies:** D1-R1 helpful but not required. **Risk:** low.
- **Success measure:** the 7 targets × 4 commands scorecard regenerates in ≤ 15 minutes on one host, and two consecutive runs are identical apart from timing fields.

**D1-R8 — Split the CLI and unify the JSON envelope.**
- Move commands into `supwngo/commands/<name>.py`, registered through one decorator that owns `--json`, console redirection, budgets and exit codes.
- Every `--json` output carries `{schema_version, binary_sha256, degraded[], facts_used[]}`.
- **Impact:** a stable contract for the owner's shell-driven agents. **Effort:** S–M. **Dependencies:** none. **Risk:** low.
- **Success measure:** `cli.py` is ≤ 300 lines, and a schema-validation test passes for every command on every fixture.

**D1-R9 — Packaging and CI hygiene.**
- Delete `setup.py` and `requirements.txt`. Move unused dependencies to extras, set `requires-python` to what is tested, and fix the Dockerfile with a Ghidra/JDK layer.
- Add pytest tiers (`unit`, `fixture`, `corpus`, `tool`).
- If GitHub Actions cannot run (offline requirement), put a `make ci` target in the tree and run it as a pre-merge hook on a local runner.
- **Effort:** S. **Dependencies:** none. **Risk:** none.
- **Success measure:** `docker build` succeeds and `supwngo decompile` works inside the container; the `unit` tier completes in under 90 s.

**D1-R10 — Collapse the planning documents.**
- Replace `docs/roadmaps/*` with a single living `ARCHITECTURE.md` (the target design above) and a single `ROADMAP.md`. Archive the rest. Each ADR takes one decision: KB, planner, Ghidra-first, legacy removal.
- **Effort:** S. **Dependencies:** none. **Risk:** none.
- **Success measure:** the number of documents with a stale `Status:` header is 0.

### 3. Hypotheses and experiments

**D1-H1 — The engines disagree on most binaries today.**
- Experiment: run `pwn --json`, `template -t auto --json`, `explain --json` and `autopwn --json --no-legacy` over every corpus binary, map the outputs to a common technique vocabulary, and compute four-way agreement.
- Falsifier: agreement of 80% or more. In that case D1-R2 is polish, not a priority.

**D1-H2 — At least 30% of `exploit/` is unreachable from any CLI command.**
- Experiment: static import-graph reachability from the `cli.py` commands plus the two registries, cross-checked with `coverage` over the retest matrix.
- Falsifier: under 15% unreachable.

**D1-H3 — The Ghidra 180 s timeouts are per-invocation overhead, not decompilation cost.**
- Experiment: time a headless import and auto-analysis alone, then `-process` with the script against a persisted project, on rocket_blaster_xxx and snow_scan.
- Falsifier: the warm `-process` run still exceeds 30 s on rocket_blaster_xxx. Then the problem is the script or the environment, and D1-R3's cache will not rescue it.

**D1-H4 — Static frame-based offset inference beats the nine dynamic finders.**
- Experiment: write 20 gcc and mingw fixtures with known offsets (canary on and off, menu-gated, a `read` loop, PE), then compare Ghidra-frame offsets against `offset`.
- Falsifier: static inference is right on fewer than 80% of fixtures, or no better than the dynamic finders on the ELF subset.

**D1-H5 — FIRST_TECHNIQUES ordering is overfit.**
- Experiment: cold-measure the archived R3, R4 and R5 held-out corpora with the current order and with a random permutation of the first block.
- Falsifier: the held-out solve rate is within 10 points of in-sample, and the random order loses more than 15 points. That would show the list encodes real signal and should become planner priors.

**D1-H6 — More stringly-typed comparisons are live bugs.**
- Experiment: grep every comparison against `protections.*`, `arch` and `relro` literals, and check each against the producer's value set.
- Falsifier: RELRO is the only mismatched field.

**D1-H7 — Detection is locked inside executor gates.**
- Experiment: add a throwaway `supwngo gates <bin> --json` that reports every executor's `is_applicable` and `skip_reason`, then compare it with `pwn` and `report` on the HTB set.
- Falsifier: the gates add no correct method beyond what `pwn` already lists on any of the seven. Then the missing piece is detector depth, not plumbing.

### 4. Best-in-class gap

- **CodeQL and Joern: extract once, query many.** A database is built per target, and every analysis is a query against it. This is D1-R1 and D1-R3. Copy the shape (a persistent per-binary artefact with versioned extractors); do not copy the query language.
- **BAP's Knowledge Base.** Analyses declare what they provide, and facts are computed lazily and memoised per object. This is the right model for the analyzer registry. Copy the provides/requires contract; skip the lattice and merge algebra, which the orphaned `schema/` already tried to perfect.
- **Binary Ninja (BNIL, `.bndb`, Workflows) and Ghidra (program database, prioritised analyzers).** Analysis results persist, and consumers read stack-frame layouts, cross-references and types from the database. supwngo re-derives these with regexes over objdump text in 28 places. Copy by treating Ghidra's database as the system of record; do not write another disassembly scraper.
- **The angr ecosystem (Shellphish: `rex`, `angrop`, `archr`, `patcherex`).** Target description (`archr`), crash-to-primitive (`rex`) and chain synthesis (`angrop`) are separate packages with narrow interfaces. supwngo declares `angrop` as a hard dependency and imports it at one site (`rop/chain.py:199`). Copy the split between target, primitive and synthesis. Do not copy symbolic-first exploitation, which the S4 timeouts already show is the wrong default.
- **Mayhem and the DARPA CGC systems.** Every component ran under a hard resource budget set by a scheduler, and proofs of vulnerability were re-validated out of process. supwngo's `VerificationReceipt` is genuinely on par in spirit; the scheduler side is absent. Copy per-job budgets and isolation (D1-R7); skip the distributed infrastructure.
- **AIxCC finalists (Team Atlanta's Atlantis, Trail of Bits' Buttercup, Shellphish's ARTIPHISHELL).** As I understand their public write-ups, LLM agents sit on top of a deterministic tool substrate with structured, cacheable outputs, and results are validated by execution (UNVERIFIED in detail). The transferable lesson is that agents need cheap, idempotent, JSON-emitting tools, which is D1-R1 and D1-R8. Their Kubernetes-scale orchestration and budget arbitrage are not transferable to a single maintainer with four air-gapped nodes.
- **pwntools and Zeratool** set the template baseline: a small, predictable script with clearly marked holes. supwngo's verified-success script path meets it; the `template` command does not.
- **What supwngo does better than most:** attribution discipline (candidate provenance, echo-ambiguous receipts, negative controls). Keep it, and move it from the benchmark layer into the fact layer.

### 5. Questions for the owner

1. **Is autonomous exploitation still a goal, or is the product "right method + offset + completable template"?** If the latter, about 37k LoC of executors becomes an optional verifier and the planner and KB become the product. That reorders the roadmap.
2. **Will you approve deleting the legacy engines and the unreferenced `exploit/` modules now (decision D-1), given 0/7 attributed?** D1-R5 and roughly 30k LoC depend on it.
3. **Is Ghidra the system of record?** That means accepting a JVM dependency and per-binary cold start in exchange for dropping angr from the default path. If it is not, D1-R3 and D1-R4 need a different backend, and PE "decompile + offset" has no obvious air-gapped route.
4. **Who is the primary user: a human at a terminal, or your agent fleet calling the CLI?** If agents, the stable JSON envelope and `facts` command outrank `explain` and Rich output, and the 29k-line walkthrough package is the wrong investment.
5. **Are the archived R3–R5 held-out corpora still usable as a blind set?** They are the only cheap defence against overfitting to seven targets, and D1-H5 needs them.
6. **Does CI actually run anywhere?** If Actions is unavailable for offline reasons, I would specify a local runner; if it is merely unused, switching it on is a one-day job.
7. **Should `schema/` be salvaged as the KB's provenance vocabulary, or deleted?** I recommend keeping about 200 lines and deleting the rest.
8. **Is `kernel/` (6k LoC) in scope for "best binary RE/VR tool"?** If not, it should move to a separate package so it stops taxing imports, tests and reviews.
