# D2 — Reverse-engineering and vulnerability-discovery depth

Everything below comes from reading the code; nothing was run. Statements about Ghidra/angr runtime behaviour are marked UNVERIFIED. `supwngo/kernel/` was only skimmed, and `_review/SCORECARD.md` was absent.

### 0. Verdict

- **There is no program-analysis layer.** `analysis/` and `vulns/` are import-name lookups plus linear capstone sweeps with string-matched operands. The real per-binary reasoning lives in `exploit/` as regex over `objdump` text: 263 `objdump`/`nm` references across 46 files. That is roughly 46 private mini-analysers, with no shared IR, xrefs, frames or call-site arguments.
- **`report` returning 0 findings is by design, not by bug.** Two of the five wired detectors are literally `return []`; the stack detector reports only on PLT presence and suppresses `read` when canary and PIE are both on. S6 as scoped (gate tweaks, named allocators) will hit "≥2 of 3" and leave the approach unchanged.
- **Address-space bugs silently void results on PIE (3 of 7 targets).** pwntools, angr and Ghidra each use a different image base and nothing rebases. The angr decompile "success" on rocket_blaster_xxx is very probably the 32-character failure sentinel.
- **"Symbolic" and "fuzzing" are scaffolding.** The Driller module cannot produce an input from a concrete seed, symbolic exploration is unbudgeted and in-process, and neither feeds `report`. No detector consumes dynamic evidence unless a caller hands it a `CrashCase`.
- **Highest-leverage move:** one cached, whole-program Ghidra export per binary (functions, call graph, xrefs, stack frames, call-site arguments, decompiled C), with detectors, offset inference, win-function discovery and LLM hooks rewritten as queries over it. This one artefact delivers "offset on all", "decompile on ELF and PE", and the recall fix.

### 1. Findings

**D2-F1 — critical — Two of five `report` detectors are stubs; the rest are import-table lookups.**
- `vulns/heap.py:109` and `vulns/integer.py:96` are `return []` ("rely on dynamic testing"), but `report` never passes a crash (`reporting/adapter.py:98`, `cls(binary).detect()`).
- `vulns/stack_bof.py:120,136,158` report on `func_name in self.binary.plt`, with the PLT stub as the finding address.
- `stack_bof.py:155-157` drops `read`/`recv` when canary and PIE are both set — exactly the profile of the heap targets auth-or-out and bon-nie-appetit, which then fall through to the heap stub.
- Static binaries have no PLT, which is why sick_rop finds nothing; the same holds for snow_scan.
- Why it matters: recall is structurally near zero for anything that isn't `gets`/`strcpy` in a dynamic, unprotected binary. Precision is unmeasured because no negative corpus exists.

**D2-F2 — critical — No shared program representation; RE logic is duplicated as objdump regex.**
- `exploit/walkthrough/facts.py:653` derives a frame offset from `re.findall(r"-0x([0-9a-f]+)\(%rbp\)", out)` and takes `max()`.
- `exploit/offset_finder.py:946-1060` runs `objdump -d` three separate times with a 10 s timeout.
- `analysis/static.py:241-256`: `_find_callers` returns `[]` by documented decision, so the "analysis" package has no xrefs.
- Why it matters: every new technique re-implements disassembly parsing, and each silently fails on stripped binaries, static binaries, PE, and frames without a frame pointer. This is also why the five engines disagree: they do not read the same facts.

**D2-F3 — high — Image-base mismatch between pwntools, angr and Ghidra on PIE.** (UNVERIFIED at runtime; no rebasing exists in the code.)
- `_angr_subprocess.py:76` builds `angr.Project(binary_path, auto_load_libs=False)` with no `main_opts`; angr's default PIE base is 0x400000, pwntools' is 0.
- `_op_dataflow` (`:169`) and `_op_decompile` (`:229-230`) look up `cfg.kb.functions.get(func_addr)` with a pwntools address. `_op_decompile` prefers the address over the name, so even named lookups miss.
- `dataflow.py:254-263` compares angr-space call targets against pwntools PLT addresses; on a miss, `dataflow.py:231-232` returns empty results labelled backend "angr".
- `decompile.py:363-371` passes no image base to Ghidra (default 0x100000 for PIE ELF), so `addr:` selectors miss and returned addresses disagree with the rest of the tool.

**D2-F4 — high — Decompile architecture: one JVM and one full auto-analysis per function, no caching.**
- `decompile.py:363-371` runs `-import … -postScript … -deleteProject` every call, with no `-analysisTimeoutPerFile`, no analyser tuning, and stdin left inherited.
- `SupwngoDecompile.java:115` decompiles exactly one function; `decompile_all` (`decompile.py:609-612`) would launch Ghidra up to 100 times.
- The CLI defaults to `main` (`cli.py:2070-2071`). The script's first-function fallback (`java:88-96`) only fires on an empty selector, which the CLI never sends, so sick_rop and ancient_interface get nothing.
- `_find_ghidra` (`decompile.py:166-171`) only checks fixed paths, not versioned install directories.
- Variables are re-parsed from C text with regex (`decompile.py:522-564`), although Ghidra already holds typed stack variables with offsets.

**D2-F5 — high — angr fallback reports a failure sentinel as success.**
- `_angr_subprocess.py:244` sets `code = f"// Decompilation failed for {func.name}"` and returns `found: True`. For `main` that string is exactly 32 characters, matching the brief's "rocket: 32 chars of code".
- `decompile.py:510-520` accepts it as a result.
- Probable root cause (UNVERIFIED): `CFGFast()` without `normalize=True` and `cfg=cfg` rather than `cfg.model` at `:226,240`.

**D2-F6 — high — `heap_advanced.py` is blind and noisy even on libc-malloc binaries.**
- It iterates `binary.symbols` (`:171`), which includes objects and pwntools' `plt.*`/`got.*` pseudo-symbols, and linearly disassembles a fixed 0x500 bytes from each (`:177`). Adjacent functions are re-scanned and sites double-counted; stripped binaries have no coverage.
- Call targets are matched by substring on `op_str` (`:186`).
- `_detect_heap_overflow` matches `str(plt_addr)`, a decimal string, against hex operands (`:377`), so it can never fire. `integer_advanced.py:384` has the same dead check.
- UAF is defined as "no `mov …, 0` or `xor r, r` within 4 instructions after `free`" (`:244-246, 275-288`). `xor eax, eax` before the next call satisfies it, and a missed case emits both a UAF and a "CRITICAL" tcache-poisoning finding (`:404-419`).
- Double-free is "≥2 `free` calls in one function" (`:327`). It returns early when `free` is not in the PLT (`:220`), which is the auth-or-out blindness.

**D2-F7 — high — `UAFDetector` cannot emit a finding.**
- `uaf.py:105-110` constructs `UAFVuln(name=…, severity="medium", …)`. `UAFVuln` has no `name` field and `vuln_type` is required (`detector.py:67`), so this raises `TypeError`, swallowed at `uaf.py:135` at debug level. The same happens at `:127`, `:161`, `:286`, `:491`.
- It is exported in `vulns/__init__.py` but excluded from `report` (`adapter.py:55-60`).
- `OffByOneDetector` is also excluded, and its logic is a count of `0x76`/`0x7e` bytes in `.text` (`off_by_one.py:166-169`) — operand bytes included.

**D2-F8 — high — Data-flow is a label, not an analysis.**
- `dataflow.py:234-247` lists calls in a function and tags them source or sink; no flow connects them.
- `get_reaching_definitions` and `get_live_variables` return never-populated dicts (`:428-450`).
- The capstone fallback taints only `rax` after a source (`:328`) and never the buffer argument, so `read(0, buf, n); printf(buf)` is invisible.
- `find_taint_paths` (`:399-412`) runs an unbounded in-process `simgr.explore` and ignores the source.
- `analyze_integer_operations` flags every `add`/`sub`/`imul`/shift (`:555-579`).

**D2-F9 — high — Symbolic and hybrid fuzzing are non-functional as discovery.**
- `driller.py:193` seeds concrete stdin, so no path constraint depends on input. `_is_interesting_branch` is "has any constraint" (`:249`), and `_solve_alternate_path` negates only the last constraint and evaluates `stdin.content[0]` (`:270-284`).
- `angr_engine.py:148` "preloads" stdin by writing to it.
- `explore` (`angr_engine.py:253-261`) checks the wall clock only between `step()` calls, in-process. This is the failure class S4 fixed for CFG and left here.
- There is no library-function handling for static binaries, so symbolic execution walks into inlined libc.

**D2-F10 — medium — Fuzzing wrappers exist but are detached from detection.**
- `fuzzing/afl.py:190-199` has `-Q`, `-O` and cmplog flags, but nothing feeds triaged crashes into `report`.
- Crash triage replays only as `run < file` under gdb with a 30 s cap (`crash_triage.py:282,302`). There is no argv/file/menu vector, no sanitiser-style oracle, no dedup by faulting frame. The heap targets need stateful menu dialogue.

**D2-F11 — medium — Win-function discovery is overfit by name and over-matches by behaviour.**
- `offset_finder.py:887` hard-codes `"fill_ammo"`, the evaluation target's own function, in `WIN_NAMES`. The brief says a second list in the strategy engine lacks it, so the lists diverge.
- `_find_by_file_ops` treats any function calling `read@plt` as "opens a file" (`:969-973`).
- The right signal — an xref from `./flag.txt` or `/bin/sh` to its enclosing function, then to open/system — needs the xrefs F2 says are missing.

**D2-F12 — medium — Format-string detector: the best of the set, still fragile.**
- It scans only `.text` (`format_string.py:393-396`) and only immediate call targets (`:421`), so it misses `-fno-plt` and static binaries. A linear 15-instruction window crosses basic blocks (`:470`), and 32-bit is "assume unsafe" (`:462-464`).
- It is also the only detector that executes the target during `report` (`:550`), a side effect on a command documented as static.

**D2-F13 — medium — ELF/x86-only core despite claims.**
- `core/binary.py:115` claims "optional PE support" and `_lief_binary` is declared (`:126`), but the load path is `pwn.ELF` plus pyelftools (`:205,256`). A PE yields an empty `Binary`; `report` then refuses it.
- `decompile` may work on PE by accident, since Ghidra receives the raw path (UNVERIFIED).
- Every detector hard-codes `CS_ARCH_X86` and the SysV argument registers (`heap_advanced.py:161-166`).
- `cfg.py:220-223` picks the first executable section (`name == '.text' or flags & 0x4`), which in a normal ELF is `.init`.
- `Binary.strings` returns file offsets labelled as addresses (`binary.py:571-578`).

**D2-F14 — medium — Canary false positive on static binaries.**
- `binary.py:365` and `protections.py:139` take pwntools' symbol-presence check, and static glibc always contains `__stack_chk_fail`. This matches the snow_scan false positive in the brief (UNVERIFIED as the cause).
- The canary bit gates detectors (F1) and offsets, so this is not cosmetic. The correct measurement is per function.

**D2-F15 — medium — No ground truth, so precision and recall are unknowable.**
- I did not search `tests/`, so "no labelled corpus" is inferred from the brief's 7-target set.
- Detector confidences are hand-typed constants (0.4, 0.5, 0.7 in `heap_advanced.py`).
- `decompile.py:627-637` regex-greps decompiled C for `strcpy(` and calls the hits vulnerabilities.

**D2-F16 — low — `kernel/` is exploit-technique templates** (modprobe, msg_msg, pipe_buffer, cross_cache), not kernel RE or VR (UNVERIFIED depth). 6k LoC here is off the critical path of the PASS criteria.

### 2. Recommendations

**D2-R1 — Build `supwngo/facts/`: one whole-program Ghidra export, cached by sha256.**
- Replace `SupwngoDecompile.java` with an exporter run once per binary, writing JSON or SQLite under `~/.cache/supwngo/<sha256>/`:
  - functions (entry, size, name, thunk/library flag) and call graph;
  - string and data xrefs with the enclosing function;
  - per-function stack frame (variable offset and size relative to the return address, from Ghidra's frame model);
  - per call site, the callee and each argument resolved from high P-code to constant, stack address, global address or unknown;
  - decompiled C for every non-library function.
- Pin the image base once (`-loader-imagebase 0` for PIE ELF, verify the flag on 12.1.3) and store `image_base` so every consumer rebases through one function. Apply the same base to angr with `main_opts={'base_addr': …}`.
- Use Java now. Evaluate PyGhidra separately: the wheel should ship inside the Ghidra distribution and install offline (UNVERIFIED on this host).
- Add `-analysisTimeoutPerFile` and `stdin=DEVNULL`, and disable the analysers that dominate on static binaries.
- Impact: unblocks R2–R6 and decompile on ELF and PE with no `main`; removes the 180 s-per-function cost. Effort: M. Dependencies: none. Risk: a Ghidra version-coupled Java API; mitigate with a schema version and golden-file tests.
- Success measure: on the 7 ELF targets plus 4 mingw PE fixtures, the export completes in under 180 s cold and under 2 s warm on 11/11. `decompile` with no `-f` returns non-sentinel C for the entry-reachable function on 11/11.

**D2-R2 — Static offset inference as a facts query.**
- For each input-sink call site (`read`, `fgets`, `gets`, `scanf %s`, `recv`, `memcpy`, a raw `syscall` with rax=0, `ReadFile`, plus fixed-stride copy loops), report the destination frame offset, the constant length if known, the distance to the saved return address, and whether a canary slot lies between.
- `offset` becomes static-first; cyclic and gdb become a confirmation step that can fail without failing the command.
- Impact: directly meets "offset on all", including PE and menu-driven targets. Effort: S–M. Dependencies: R1. Risk: custom parsers (snow_scan's BMP loop) need the loop pattern or R5.
- Success measure: correct offset (±0) on at least 9 of 10 stack-BOF binaries from the R7 corpus per optimisation level, and on 4/4 of the eval set's stack targets. The command never raises.

**D2-R3 — Rewrite detectors as evidence-graded queries; delete the PLT detectors.**
- Grade every finding: E0 import-only (never shown as a finding), E1 site-level static (sink, destination size, length), E2 path-level (decompiler or LLM argued, with cited lines), E3 dynamically confirmed.
- Initial query set:
  - stack BOF: constant length greater than distance to frame end; unbounded sinks.
  - format string: format argument not a constant, replacing F12 so static binaries are covered.
  - allocator-role inference: name patterns such as `*alloc*`/`*free*`, wrappers of malloc/free/mmap/brk, pointer-returning functions whose results are stored into global tables. This makes `ta_alloc` visible without hard-coding it.
  - dangling slot: a free-role call on a global-table slot with no store of 0 to that slot on any path to return, via Ghidra P-code def-use within the function.
  - integer: user-derived value feeding a signed compare, then a size or index.
  - off-by-one: `buf[n] = 0` after a read of `n == sizeof`, or a `<=` bound against the allocation size.
- Impact: recall on the real bug classes; findings carry function, site and offset. Effort: M–L. Dependencies: R1, R7. Risk: FP growth, controlled by R7's patched twins.
- Success measure: on the R7 held-out split, recall ≥ 0.7 and precision ≥ 0.6 at E1+ for stack/format, and recall ≥ 0.4 for heap/integer. On the eval set, the known bug's function is named in 6/7 reports.

**D2-R4 — Dynamic confirmation oracle (E3), offline.**
- A single `confirm(finding, input_recipe)` runner: native under gdb for ELF x86-64, Qiling/Unicorn for PE and foreign architectures. Qiling needs no wine, but its Windows API coverage is partial — fine for console fixtures; treat wine as optional.
- A cheap heap oracle via `LD_PRELOAD` for libc malloc (double free, write past chunk, use after free), or QASan under AFL++ QEMU mode. For in-binary allocators, hook the inferred alloc/free roles from R3 by address.
- Move `symbolic/` exploration into the existing budgeted subprocess. Use angr only for directed tasks: under-constrained execution from the suspect function, and reaching a site. Delete `driller.py` or replace it with AFL++ cmplog.
- Impact: turns "maybe" into "proven"; gives the LLM a verifier. Effort: M. Dependencies: R1, R3. Risk: environment modelling for menu binaries, which need R5 for dialogue.
- Success measure: at least 5 of 7 eval findings reach E3 with a stored reproducer. Zero E3 findings on patched twins.

**D2-R5 — LLM hooks at three narrow, verifiable points.** All via the vLLM OpenAI-compatible endpoint, shell-drivable, JSON-schema output.
- Per-function triage over R1's decompiled C plus frame and call-site facts: `{bug_class, lines, sink, claimed_offset, confidence}`. Claims are checked against facts (R2) or the oracle (R4). Unverified claims are shown as hypotheses at E2, never as findings.
- Role naming on stripped or static code (allocator, parser, menu handler, win), cached in the facts DB.
- Input-recipe synthesis: the menu dialogue or file format needed to reach the site, verified by the R4 breakpoint being hit.
- Expose facts as CLI subcommands (`supwngo facts funcs|xrefs|frame|callsites|decomp --json`) so the owner's agentic CLI can drive it Big-Sleep-style.
- Impact: this is the realistic route to UAF, off-by-one and integer recall. Effort: M. Dependencies: R1; R4 for verification. Risk: hallucination, bounded by the verify-or-demote rule, and local-model quality.
- Success measure: on R7 held-out heap/integer cases, verified recall improves by at least 25 points over R3 alone, with at most 10% of verified claims wrong on patched twins.

**D2-R6 — Library identification for static and stripped binaries.**
- Run signatures before detection. Options: Ghidra FunctionID with a `.fidb` built from the glibc/musl versions in the libc database (BSim is the fuzzier alternative), or rizin FLIRT sigdb (small, offline-friendly), or angr's FLIRT analysis.
- Mark library functions in facts; detectors and the LLM skip them, and sinks resolve by identity instead of PLT.
- Impact: snow_scan (877 KB static) shrinks to tens of user functions; makes R3 work without PLT. Effort: M. Dependencies: R1. Risk: version coverage.
- Success measure: on static builds in R7, at least 90% of libc sink functions named correctly, and user-function count within 20% of the dynamic twin.

**D2-R7 — Ground-truth corpus generator, the anti-overfitting control.**
- Around 30 small C templates per CWE (121, 122, 134, 190, 193, 415, 416), each with a patched twin.
- Compile across gcc × {-O0, -O2} × {canary on/off} × {PIE on/off} × {dynamic, static} × {stripped or not} × {ELF64, ELF32, mingw PE64/PE32}.
- Labels come from the build: bug function, sink line, and true offset from DWARF in an unstripped sibling. Add wrappers for custom-allocator, menu-loop and file-parser shapes.
- Fix a 70/30 dev/held-out split by template. The HTB seven become a smoke test only. Rule: no identifier from any evaluation binary may appear in the source (F11 violates this today).
- Impact: makes every other measure falsifiable. Effort: M. Dependencies: none. Risk: synthetic bias; add roughly 20 public binaries (ROP Emporium, how2heap, cb-multios Linux ports) as a second held-out tier.
- Success measure: the corpus builds reproducibly offline with at least 800 labelled binaries, and the scorecard emits precision, recall and offset accuracy per class and per build axis.

**D2-R8 — Correctness fixes that should not wait.** Effort S each; no dependencies except where noted.
- Treat the `// Decompilation failed` sentinel as failure; pass `normalize=True` and `cfg.model` (F5).
- Rebase angr and prefer name over address (F3).
- Fix `.text` selection (F13) and the decimal comparisons (F6).
- Fix `UAFVuln` construction or delete the class (F7).
- Per-function canary detection (F14), on top of R1.
- Remove target-specific names (F11).
- Success measure: a regression test for each. `decompile --angr` on a PIE fixture returns real C or a clear failure, never 32 characters.

**D2-R9 — Format and architecture policy.**
- Add a `BinaryFacts` front door backed by R1, with LIEF for header-level PE/Mach-O metadata. Stop extending `pwn.ELF`-centred `Binary`.
- Scope explicitly: ELF and PE on x86/x64 now; AArch64 and ARM next, essentially free through Ghidra facts plus Qiling; MIPS and firmware later; Mach-O and kernel parked.
- Impact: removes x86 hard-coding from detectors by construction. Effort: M. Dependencies: R1. Risk: scope creep.
- Success measure: the R7 PE cells and one AArch64 cell pass R2's offset measure with no arch-specific detector code.

### 3. Hypotheses and experiments

- **D2-H1 — Ghidra's frame model alone yields the correct offset on at least 6 of 7 eval targets.** Experiment: a throwaway GhidraScript dumping stack variables and call-site arguments for input sinks; compare by hand with known offsets. Falsifier: fewer than 5 of 7 correct; then offsets need R4/R5, not just R1.
- **D2-H2 — The 180 s CLI cap is contention or stdin, not analysis cost.** Experiment: run the exact `analyzeHeadless` command from `decompile.py:363-371` on rocket_blaster_xxx alone, with `</dev/null`, timed, then again while the scorecard runs. Falsifier: over 120 s alone with stdin closed; then auto-analysis itself is the cost and analyser tuning is mandatory.
- **D2-H3 — The 32-character rocket result is the failure sentinel.** Experiment: print `result.code` from `decompile --angr --json`. Falsifier: the code is anything other than `// Decompilation failed for main`.
- **D2-H4 — On PIE targets, `dataflow -f <addr>` returns empty with backend "angr".** Experiment: run it on sabotage's `main` address and count sources and sinks. Falsifier: non-empty, correctly named sinks.
- **D2-H5 — A local open-weight model given one function's decompiled C plus frame facts names the right bug class and function on at least 4 of 7 eval targets**, and stays above 50% on R7 held-out heap cases. Experiment: 7 prompts, temperature 0, fixed schema, scored blind. Falsifier: 3 or fewer of 7, or under 30% on held-out; then a local-model-only LLM route is not viable for heap bugs.
- **D2-H6 — Allocator-role inference finds `ta_alloc`/`ta_free` without names.** Experiment: on a stripped auth-or-out, rank functions by pointer-returning results stored to a global table and pointer-consuming calls on the same slots. Falsifier: the true pair is not in the top 3.
- **D2-H7 — Detector performance falls sharply from -O0 to -O2.** Experiment: R7 scorecard split by optimisation level. Falsifier: under 10 points of recall difference. If confirmed, all rbp-relative regex logic is a dead end, not just technical debt.
- **D2-H8 — AFL++ QEMU with cmplog finds the snow_scan BMP overflow from a valid 1×1 BMP seed within 10 CPU-minutes.** Falsifier: no crash in 60 minutes; then parser bugs need directed symbolic execution or LLM seed synthesis.

### 4. Best-in-class gap

**CGC era.**
- Mayhem's core idea was hybrid concrete/symbolic execution with *verification by construction*: every reported bug came with an input.
- Mechanical Phish composed angr CFG and value-set analysis, AFL, Driller, Rex for crash-to-exploit, and angrop for chains.
- Xandra showed that fuzzing plus good triage beat heavier symbolic stacks operationally.
- supwngo has the module names but not the composition: no stage consumes another's output (F9, F10).
- Copy: the proof-carrying finding (R4) and crash-to-primitive classification as the hand-off to exploitation.
- Do not copy: whole-program symbolic exploration or a fuzzing farm. CGC binaries were small with seven syscalls; real static glibc binaries blow up, and a single maintainer cannot run the infrastructure.

**AIxCC era (Atlantis, Buttercup, ARTIPHISHELL and peers).**
- These are source-available, harness-driven, sanitiser-verified, and use LLMs for seed and grammar generation, harness writing, triage and patching.
- Copy: the division of labour — the LLM proposes, a sanitiser-like oracle disposes — and LLM-generated input grammars for parsers and menu protocols (R5).
- Do not copy: source-level instrumentation, patch generation, or cloud-scale orchestration. None applies to binary-only, offline use.

**Big Sleep / Naptime-style LLM vulnerability research.**
- The model is an agent with a code browser, debugger and scripting sandbox. It reads code like an auditor, forms a hypothesis, and must produce a reproducer.
- This is the most transferable design here, and it needs exactly what supwngo lacks: a queryable, cached, address-consistent facts interface (R1) and a confirmation tool (R4). Shell subcommands are sufficient, matching how the owner's agents already work.
- Do not copy: reliance on frontier cloud models. Design the schema-and-verifier loop so a weaker local model degrades to more hypotheses, not wrong findings.

**Commercial and open RE practice.**
- Binary Ninja, IDA with Hex-Rays, and Ghidra each give analysts a single persistent database with types, xrefs and an IL. Checkers written on those ILs are tens of lines each because the IL does the work.
- cwe_checker (Rust on Ghidra P-code, with CWE-121/416/190 style checks and a pointer-inference value analysis) is the closest open tool to what `vulns/` claims to be. Evaluate it as an offline subprocess baseline before writing R3 from scratch, and adopt its checks wherever it already beats R3 on the R7 corpus.
- For heap specifically, angr's heaphopper and Shellphish's how2heap give technique ground truth worth mining for corpus templates rather than hand-typed strings like those at `heap_advanced.py:421-527`.

**Bottom line on "best in existence".** Not reachable by breadth. A defensible niche is: offline, binary-only, facts-backed, with every finding either dynamically confirmed or explicitly labelled a hypothesis, and a static offset on every stack sink across ELF and PE. No open tool packages that today.

### 5. Questions for the owner

1. **Is a hard dependency on Ghidra acceptable** (JVM, roughly 1 GB), with angr demoted to an optional directed-symbolic helper? If supwngo must work without Ghidra, R1 needs a second, weaker backend (rizin), and effort roughly doubles.
2. **Is "right method" satisfied by an E2 hypothesis, or must the tool show evidence?** The PASS criteria reward listing a technique, which is achievable by listing everything. I recommend adding "the report names the bug's function and site" to the criteria; otherwise detection quality is never measured.
3. **Is running the target during analysis always permitted?** `report` already does so (F12). If analysis must sometimes be static-only (malware-adjacent or firmware samples on the wider platform), R4 needs an explicit `--no-exec` mode and the scorecard needs two columns.
4. **Which local models are actually served, and at what context length?** If H5 fails on them, is a cloud model permitted for evaluation only, to separate "idea wrong" from "model too weak"?
5. **Does PE really stop at decompile plus offset?** With R1/R2 that is cheap; PE vulnerability *detection* comes nearly free from the same facts, but PE dynamic confirmation (Qiling or wine) does not. Knowing whether Windows exploitation is ever in scope changes whether R4 invests in Qiling now.
6. **Will you delete code?** `symbolic/driller.py`, the honggfuzz/libFuzzer wrappers, the RetDec path, `uaf.py`/`off_by_one.py` detectors, `analysis/diff.py`/`patch_diff.py` and arguably `kernel/` are unmaintained surface that advertises capability the tool lacks. Keeping them costs credibility with users and review time on every sprint.
7. **Are stripped static binaries with unknown libc a priority?** That decides whether R6 is sprint 2 or sprint 6.
