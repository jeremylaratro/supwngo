### 0. Verdict

- **The review is measuring the wrong engine.** The tree records the canonical pipeline solving 7/7 HTB targets to `SHELL_ACCESS` by 2026-09-28 (`CHANGELOG.md:1165`), but the scorecard has no `solve`/`autopwn` column. BRIEF §4's "0/7" is the 2026-09-26 number. The 7/7 is UNVERIFIED here: the cited `benchmark/results_htb/` JSON is not in this export, and nothing shows it was re-run after S1–S5.
- **`pwn`'s method selector is a constant classifier with decorative confidences.** Its 2/7 is really 1/7 discriminative; ancient_interface "passes" on a label emitted identically for five targets.
- **`template` is not a template system.** It instantiates the legacy `AutoExploiter`, runs the target, silently substitutes a different technique than requested, drops `--offset` on its commonest path, and emits `offset = 0` scripts that run "successfully".
- **"Offset on all" is 0/7 by design.** All five offset implementations in the tree are crash-driven or a first-`sub rsp` regex; none relates the sink's destination buffer to the saved return address.
- **Highest-leverage move:** make one `MethodPlan`, built from the pipeline executors' static gates plus a static sink-to-frame offset analysis, the single source for `pwn`, `template`, `offset`, `report` and `explain`. S6 as drafted moves none of the owner's four criteria and should be replaced.

### 2. Recommendations

**D3-R1 — Re-baseline with `solve` and `explain` columns and a multi-label truth file.**
- Add `benchmark/truth/<target>.yaml` with: `methods_accept` (a set), `methods_reject`, `vuln_function`, `sink`, `distance {kind, value}`, `canary_offset`, and `components {win, ret2, args, libc}`.

- Impact: the roadmap rests on true numbers. Effort: S. Dependencies: none. Risk: the 7/7 may have regressed, which is itself the finding.
- Success: a scorecard with `solve` cells for 7/7 targets, each backed by a JSON artifact committed in-tree.

**D3-R2 — One `MethodPlan`, owned by the pipeline registry, rendered by every command.**
- New `supwngo/plan/`: `build_plan(binary, known: KnownFacts, execute=False) -> list[MethodPlan]`.
- `MethodPlan` fields: `technique_id`, `family`, `evidence[]` (address plus disassembly), `facts{}` with provenance in `{static, measured, operator, unknown}`, `required_inputs[]`, `distance`, `script_builder`.
- Populate by calling each executor's static gate. Extend the contract with `plan(context) -> PlanFacts | SkipReason`, formalising what `_gate` and `analyse()` already return.
- Generic families (ret2win, ret2libc, ROP, shellcode) get plans from R3 and R4.
- `pwn` prints plans; `template -t auto` renders `plans[0]`; `report` findings are plans with evidence; `explain` consumes the same object.
- `StrategySuggester` becomes a thin fallback for un-gated families. `exploit --auto` is deprecated.
- This subsumes RT-08 and RT-10.
- Impact: ends the disagreement between engines and puts the method into `pwn`. Effort: M. Dependencies: R1. Risk: some gates have a live half, which must sit behind `execute=True`.
- Success: on HTB-7, `pwn --json` top-1 is in `methods_accept` for at least 6/7 with no execution, and `pwn`, `template` and `solve` name the same `technique_id` on 7/7. On the corpus, top-1 accuracy beats the majority-label baseline by at least 30 points.

**D3-R3 — Static distance inference in `supwngo/analysis/stack_layout.py`.**
- *Estimator A (capstone, no JVM):*
  1. Recover functions from symbols, call targets and prologues, so stripped and no-`main` binaries work.
  2. Find sinks: PLT/IAT calls (`read`, `gets`, `fgets`, `scanf("%s")`, `recv`, `strcpy`, `memcpy`, `fread`; on PE also `ReadFile`), plus raw `mov eax,0; syscall`.
  3. Backward-slice the destination argument (SysV `rsi`/`rdi`, Win64 `rcx`/`rdx`, cdecl stack) to `lea r,[rbp-X]`, `lea r,[rsp+Y]` or `mov r,rsp`.
  4. With a frame pointer, `ret_off = X + ws`. Otherwise track the stack-pointer delta from entry to the sink.
  5. Detect the canary (`fs:0x28` / `gs:0x14` stored to a slot; on PE, `__security_cookie` XOR and `__security_check_cookie`) and emit `canary_off`.
  6. Slice the length argument and emit `write_len` and `reaches ∈ {locals, canary, saved_bp, ret}`.
- *Estimator B (Ghidra, cross-format):* extend the committed Java script to export, per sink call, the stack storage of the destination. Ghidra's stack offsets are relative to the return-address slot, so the distance falls out directly for ELF and PE.
- Report both and their agreement. Never emit an unlabelled guess.
- `offset` becomes static-first; `--dynamic` adds measurement (R5).
- Non-stack plans expose their own `distance.kind`: `chunk_to_next_size`, `record_to_fnptr` (0x18), `buf_to_env` (0x20).
- Impact: 0/7 becomes achievable, and PE works without wine. Effort: M. Dependencies: Ghidra project reuse from the decompile dimension. Risk: `-O2` frames, `alloca`, and inlined or `rep movs` copies; abstain with a reason.
- Success: exact match to truth on the four HTB stack targets (sick_rop = 40 per `CHANGELOG.md:1986`), and at least 95% exact on corpus stack targets against DWARF truth.

**D3-R4 — Evidence-based win detection in one module; delete the seven lists.**

  - calls to `system`/`exec*`, or an `open → read → write` chain;
  - cross-references to `flag`, `/bin/sh` or `cat ` strings;
  - unreachability from the entry point in the call graph.
- Attach `required_args` from compare constants.
- Names are a tie-breaker only. Remove `fill_ammo`.
- Add a lint test that fails if any benchmark target name or symbol appears in non-comment code under `supwngo/`.
- Impact: rocket_blaster gets ret2win without an answer key. Effort: S–M. Risk: decoys; keep the top three with evidence.
- Success: on `objcopy --redefine-sym` copies of all win-function corpus targets and rocket_blaster, top-1 payoff address matches truth on at least 90%, with identical output before and after renaming.

**D3-R5 — Dynamic validation by breakpoint at the sink, not by crash.**

Experiment: 50 mutants with JSON in and JSON out. Falsifier: lift under 10 points. If so, keep LLMs out of the selection path.

### 4. Best-in-class gap

- **pwndbg / GEF.** `retaddr`, `canary`, `telescope` and heap tracing give exact frame facts at a breakpoint. Copy the technique (R5); do not embed the tools.
- **pwntools.** `Corefile` fault analysis, `args` magic, `ROP` and `SigreturnFrame`. Templates should lean on these and stop hand-packing zeros. Copy.
- **Zeratool.** The closest open competitor in scope: angr-driven overflow and format-string detection, then win or ret2libc selection. It derives the method from a reached vulnerable state, not from imports. Copy the principle: no method without a located sink.
- **angr `rex`/`archr`/angrop, Mayhem/AEG.** Crash state to exploit by symbolic constraint solving. Do not copy wholesale; S4 already shows angr budget problems here. Do borrow angr's stack-pointer tracking and variable recovery as an optional third offset estimator.
- **cwe_checker and BinAbsInspector.** Ghidra P-code checkers for stack overflow, UAF and integer overflow on stripped binaries. This is what RT-09 and RT-10 are reinventing with regexes. Evaluate one as a finding source feeding R2.
- **HeapHopper / ArcHeap / how2heap.** Heap techniques modelled as primitive and glibc-version to technique. Copy the table as data for plan requirements. Do not copy the model checking.
- **FLIRT / Ghidra Function ID.** Library-function identification in static or stripped binaries. Needed so R3 can find `read` in snow_scan. Copy via Ghidra FID.
- **AIxCC-style and Naptime-style agent systems.** As I understand them, their durable lesson is deterministic tools emitting evidence-bearing JSON with a verification oracle the model cannot talk past. supwngo's receipt and shell-proof verifier is already of that kind. `MethodPlan` JSON is the missing tool surface for the owner's shell-driven agents.

### 5. Questions for the owner
