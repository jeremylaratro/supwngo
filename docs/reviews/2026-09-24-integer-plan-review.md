NOT-APPROVED

Blocking issues

1. The detector contract does not prove the control flow it claims. It records whether a branch is signed, but not which edge reaches the sink/store. That matters because target 10 uses an accepted `jle`, while target 14 uses a rejecting `jg` ([plan:45](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:45), [plan:110](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:110)). The proposed analysis only mentions signedness and tainting the guarded `scanf` slot ([plan:147](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:147), [plan:153](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:153)). It must additionally prove:

   - The accepted edge reaches the truncation/read or indexed store.
   - The truncated value reaches `read`’s count argument and the destination is the local stack buffer.
   - The indexed store’s value, not just its index, is attacker-controlled. Otherwise “single attacker-chosen qword” is unjustified.
   - The computed landing slot is the slot later compared with the required immediate, and the satisfying branch reaches `win`.
   - For truncation, the maximum accepted count reaches the complete saved return address.

2. The truncation detector cannot establish the claimed 64-byte buffer size from the proposed `objdump` fields. The source declares `buf[64]` ([int_overflow.c:38](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/benchmark/corpus/10_int_overflow/int_overflow.c:38)), but the disassembly only establishes a guard immediate of 64 and a destination at `rbp-0x50`; those do not generally prove the object’s capacity. The plan nevertheless labels `(n & 0xff) > 64` as overrunning a 64-byte buffer ([plan:66](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:66)). Either consume DWARF, describe 64 only as the checked bound, or prove exploitation directly with the derived saved-return offset and required count.

3. The applicability rules omit essential full-exploit preconditions. A matching truncation pattern is not enough for the planned ret2win payload: PIE must be off or a code-address leak must exist; a canary must be absent or bypassed; a usable control target must exist; and the count must accommodate the payload. None appears in the abstention rules ([plan:200](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:200)). Likewise, absolute GDB breakpoint addresses are invalid for a PIE match. Without these gates, the family can confidently select a full route that cannot work.

4. The scores are order-dependent and can select a generic, undeliverable family. Truncation at `0.88` ties SROP’s `0.88`; negative index at `0.90` ties ret2shellcode’s `0.90`; both lose to ret2plt at `0.95` ([plan:194](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:194), [syscall.py:95](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/families/syscall.py:95), [stack_bof.py:50](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/families/stack_bof.py:50)). Ties are resolved by family-list order because selection uses plain `max` ([registry.py:95](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/registry.py:95)). Worse, ret2plt only checks ingredients—not whether any return-address overwrite is deliverable ([rop_chain.py:57](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/families/rop_chain.py:57)). This contradicts the plan’s own statement that the arithmetic bypass is the overflow precondition. A characterized direct integer route must outrank generic stack/ROP routes, or route applicability must become compositional.

5. The `0.55` “landing site not characterised” route is incompatible with a full walkthrough unless explicitly non-applicable. The plan says it “cannot claim an outcome” ([plan:198](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:198)), yet a selected walkthrough must contain a complete final exploit ([model.py:669](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/model.py:669)). If non-applicable, it must carry a rejection reason ([model.py:515](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/model.py:515)); if applicable, it can beat triage and leave `build` without an honest exploit. Define it as a rejected fallback or abstain.

6. The plan’s preflight claim is false for the existing shared builder. It says shared preflight rechecks every emitted instruction ([plan:225](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:225), [plan:282](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:282)), but `common.preflight_step` only verifies declared `G_*` gadgets ([common.py:361](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/common.py:361), [common.py:412](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/common.py:412)). Moreover, running the complete exploit bypasses all steps and calls `exploit()` directly ([render.py:552](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/render.py:552)). The integer instruction verifier must be reusable from both its diagnostic step and the final exploit.

7. The target-14 differential oracle has a false-pass path. The proposed assertion—no `try again` plus some novel output—also accepts index rejection, because `idx >= 8` prints `out of range`, which is absent from the benign `idx=0` run ([plan:257](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:257), [negative_index.c:47](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/benchmark/corpus/14_negative_index/negative_index.c:47)). Compare against both benign and rejected controls, requiring output absent from their union. Also give every literal subprocess a hard timeout: the plan explicitly identifies the one-write mutation as a hang ([plan:92](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:92)), but the test strategy only promises exit-status assertions ([plan:252](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:252)).

Target 14 already produces incorrect normalized facts, which the plan leaves untouched. `_derive_canary` treats the presence of `__stack_chk_fail` anywhere in the static binary as evidence that the target function has a canary ([facts.py:403](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/supwngo/exploit/walkthrough/facts.py:403)); the source explicitly says canary off ([negative_index.c:14](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/benchmark/corpus/14_negative_index/negative_index.c:14)). The plan’s “nothing in facts.py changes” decision needs an explicit local correction or a scoped facts fix ([plan:216](/srv/share/dev/supwngo/.claude/worktrees/agent-a18acbe1ee7dd29fc/docs/plans/2026-09-24-walkthrough-integer-family.md:216)).
