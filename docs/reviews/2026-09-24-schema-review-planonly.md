1. **BLOCKING — `asserted` beating contradictory `measured` data is unsafe.** A typo or stale hand-authored value would remain active even after the tool obtains contrary evidence; a loud warning is not a safety boundary. “The remote differs from local” is an applicability distinction, not provenance precedence. Fix: separate provenance from authority and scope. Give claims scopes such as `local-build`, `remote-target`, `host`, and `process/session`. When two claims disagree in the same scope, mark the fact unresolved and prevent safety-critical consumers from using it until the user explicitly selects or pins one. An explicit pinned override may beat measurement, but ordinary `asserted` must not.

2. **BLOCKING — The merge table is substantially incomplete.** It does not define `derived` vs `derived`, `derived` vs `measured` in either direction, `asserted` vs `asserted`, `asserted` vs `derived`, identical-value collisions, incompatible value types, retractions, or conflicts involving different confidence or timestamps. Fix: specify the complete 4×4 matrix plus same-value deduplication, type validation, deletion/tombstone behavior, and explicit conflict-resolution operations. Test both operand directions, repeated merges, and idempotence; otherwise repeated command runs may grow `conflicts[]` and `superseded[]` indefinitely.

3. **BLOCKING — Derived facts have no dependency or invalidation model.** A libc base derived from a leak remains apparently valid after the leak is superseded. Worse, an ASLR-dependent libc base is only valid for one process instance, while the document is described as build-portable. Fix: assign every claim a stable ID/revision; require `derived_from` references and the derivation expression/method; automatically mark descendants stale when an input is superseded. Add validity scopes such as build, environment, host, boot, process, and attempt. Represent facts that are only valid together as an atomic observation bundle—for example leak value, leaked symbol, libc identity, symbol offset, process/session ID, and derived base.

4. **BLOCKING — A single mandatory `target.sha256` cannot model the intended remote workflow.** An ordinary local copy has the same digest and is fine, but rebuilt, stripped, patched, or symbol-enriched surrogates will differ even when intentionally used for the same remote service. Conversely, `--context-mismatch=allow` disables too much protection at once. Fix: distinguish the analyzed artifact from the deployment target and bind each fact to the identity it requires. Record relevant identities such as full-file digest, ELF build ID, load-segment digests, libc/loader identity, and remote endpoint/profile. Refuse incompatible build-bound facts by default, but preserve or admit facts whose declared scope remains compatible. Replace the blanket `allow` with explicit rebinding or a selective list of quarantined facts the user accepts.

5. **BLOCKING — `ExploitContext` and domain blocks create two authorities for the same state.** `libc` can disagree with a libc-base fact or an `ExploitContext` field; the same applies to protections, leaks, offsets, and symbols. The plan does not say which representation consumers use or which wins during serialization. Fix: define one canonical owner for every semantic field. A sound split is: blocks contain raw observations/tool outputs; normalized facts are the only consumable claims; `ExploitContext` is a projection of those facts and never independently serialized back over them. Add cross-field invariants and reject documents where duplicated representations disagree.

6. **BLOCKING — The claimed byte-identical round trip is not achievable through the existing `ExploitContext` as described.** It cannot preserve unrelated blocks, artifacts, history, unknown extension fields, original ordering/formatting, or necessarily timestamps. `default=str` is lossy: sets become non-round-trippable strings, enum encodings are implementation-dependent, and paths lose type and lexical details. Fix: introduce a lossless `ContextDocument` model even if it is not the exploitation state object, and make `ExploitContext` a view of it. Ban `default=str`; define explicit codecs for enums, paths, sets, addresses, and large integers. Define canonical JSON precisely—preferably RFC 8785 or an equally explicit profile. Test semantic equality for arbitrary JSON/YAML input and byte equality only for canonical JSON serialized without mutation. Preserve `created` and only change `updated` on an actual mutation.

7. **MAJOR — A single Click decorator cannot make roughly 30 heterogeneous commands conform.** It can inject an option, but it cannot infer the target, capture command-specific results, handle early exits, or decide how a directory-, corpus-, remote-, multi-binary-, or no-target command maps into a one-target document. Fix: inventory every command and assign it a declared context capability and target resolver: none, single artifact, target set, directory snapshot, or remote profile. Define a common command result/emission protocol and wrap command execution centrally where possible; use explicit adapters where it is not. The conformance suite needs representative invocations and fixtures for every category, not merely inspection of the command registry.

8. **MAJOR — The “one specific build” envelope conflicts with directory and multi-target commands.** `analyze`/`fuzz` may receive directories, and corpus or distributed operations may involve many binaries. There is no meaningful singular binary digest to compare. Fix: either limit context conformance to commands operating on one target, or change the schema to support `targets` keyed by stable IDs and make facts/blocks reference a target ID. Do not overload a directory digest as though it were a binary identity without specifying a canonical manifest algorithm.

9. **MAJOR — Merge semantics exist only for facts; blocks, history, and artifacts have no update rules.** “One block per domain” is especially unsuitable for crashes, attempts, fuzz runs, leaks, and potentially gadgets, which naturally have multiple observations. Fix: define every block as either a replaceable snapshot or an append-only collection with stable entry IDs, target/scope references, timestamps, and deduplication keys. Specify artifact deduplication, history ordering, and deterministic merging. Make the whole command update transactional so facts and supporting blocks cannot be written separately.

10. **MAJOR — The minimal-document test contradicts the envelope and digest requirements.** A document containing “only `target` + one fact” lacks at least `schema_version`; it is unclear whether tool version, timestamps, history, blocks, artifacts, and even `target.sha256` are required or defaulted. Fix: publish an explicit required-field table. Require `schema_version`; distinguish author-supplied fields from loader-generated defaults; state whether missing digest means the context is unbound and what operations are then permitted. Validate defaults before merge and ensure JSON and YAML take the same normalization path.

11. **MAJOR — The target type model is internally incorrect.** `exec`, `dyn`, and `static` are not mutually exclusive values of one dimension: `exec`/`dyn` describe ELF type, while static/dynamic describes linkage; PIE commonly appears as `ET_DYN`. Fix: split this into fields such as `format`, `elf_type`, `linkage`, `pie`, `os_abi`, and build ID. Declare whether `arch`, `bits`, endian, and protections are digest-derived immutable metadata or mergeable claims so they cannot become another duplicated source of truth.

12. **MAJOR — Safe persistence and concurrent updates are unspecified.** A read-modify-write command can truncate the document on failure or lose another process’s updates. This is particularly likely when input and output are the same path. Fix: use validated temporary-file writes followed by flush/fsync and atomic rename; add locking or a document generation/revision with compare-and-swap detection. Specify behavior for symlinks, permissions, interrupted writes, and simultaneous writers, and test all of them.

13. **MAJOR — The document and artifact references are an unaddressed trust boundary.** YAML, command strings, observed debugger output, absolute paths, and artifact paths can come from an untrusted repository. They can cause alias expansion, duplicate-key ambiguity, terminal-control injection, path traversal, or accidental access to unrelated files. Fix: use a safe YAML loader with duplicate-key rejection and alias/size/depth limits; sanitize diagnostics; never execute provenance commands; resolve relative artifacts against the document location; verify digest and size before consumption; and require explicit permission for paths escaping that root. Prefer relative artifact paths for portability.

14. **MAJOR — Schema evolution and unknown-field behavior are absent.** A v1 reader must not silently interpret a future document, while lossless read/write may need to retain extensions introduced by newer producers. Fix: define exact-version acceptance, migrations, `additionalProperties` policy, namespaced extension fields, and whether unknown blocks are preserved but not consumed. Ship the JSON Schema dialect identifier and ensure format validation—especially date-time—is actually enabled.

15. **MINOR — The compatibility story is contradictory.** Adding `--context-out` does not inherently change existing `--json` output, yet the plan declares a breaking-shape change and proposes `--legacy-json`. It never explicitly states which existing flags will change. Fix: enumerate affected commands and outputs. Prefer leaving existing output untouched while the dedicated context flag emits the new schema; if existing output must change, provide the escape hatch consistently, document its lifetime, and add compatibility tests.

16. **MINOR — Provenance may leak sensitive or machine-specific data.** Full debugger commands and absolute paths undermine portability and may contain usernames, tokens, remote endpoints, or secret arguments. A digest of low-entropy normalized arguments can also permit guessing. Fix: store structured method/evidence fields, make raw command capture optional, redact known secret-bearing arguments and environment values, and document the privacy implications of sharing a context file.

17. **MAJOR — The test plan misses the failure modes most likely to corrupt exploitation state.** Fix: add tests for the full collision matrix, same-value deduplication, explicit conflict resolution, cascading derived-fact invalidation, atomic bundles, runtime expiry, merge idempotence, repeated command execution, malformed and future-version documents, unknown-field preservation, directory/multi-target commands, artifact tampering, interrupted writes, concurrent writers, and commands that fail after partially producing results. Use deterministic clocks and IDs so canonical-output assertions are meaningful.
