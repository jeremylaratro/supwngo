2. **(d) `UNKNOWN` facts make the generated script impossible to run.**

Unknown assignments call `_unknown(...)`, which is specified to raise. [`model.py:107`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:107>) [`model.py:191`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:191>) The plan renders facts as module-level assignments before dispatch. [`plan:124`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/docs/plans/2026-09-23-walkthrough-engine.md:124>)

Therefore:

```text
python3 wt.py offset
→ imports module
→ evaluates OFFSET = _unknown(...)
→ raises
→ never reaches step_offset()
```

That directly contradicts “run the resolving step.” Even if `_unknown` returned a sentinel, there is no runtime fact store or persistence mechanism. `produces` is metadata; it does not update the frozen `Fact`, module source, later process invocations, or final exploit. The generated instruction literally says “then set it here,” meaning manual source editing. [`model.py:192`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:192>) [`model.py:287`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:287>)

Validation makes this worse:

- An unknown constant counts as “available.” [`model.py:456`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:456>)
- `resolved_by` need only name an existing step; that step need not produce, compute, print, or persist the fact. [`model.py:447`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:447>)
- A fact may claim that an unrelated or earlier step resolves it.

This is the most immediate implementation blocker.

3. **(b) Rejected routes are not a decision tree and are unsafe fallback advice.**

`Route` is a flat scored record with a boolean `applicable`, free-form rationale, and free-form requirements. It has no failure symptom, branch condition, transition, action, or newly established capability. [`model.py:313`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:313>)

`fallback_routes` returns every non-primary route:

- Lower-scoring viable alternatives.
- Routes declared impossible on this binary.
- Routes rejected because required gadgets/primitives are absent.

[`model.py:407`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:407>)

“Ret2libc failed, try SROP” is actively misleading if SROP was rejected because there is no syscall gadget. A rejection explains why a route is unavailable; it is not a remedy. The existing `Fallback` type is closer to actual fallback semantics because it starts from an observed symptom. Keep route-selection explanation and runtime troubleshooting separate.

The model also cannot represent “unknown applicability”; a missing measurement is forced into true/false. It does not require any applicable route, unique route names, comparable score semantics, or agreement between `family` and the selected route.

4. **(c) The abstraction treats composable capabilities as mutually exclusive families.**

`stack_bof`, `rop_chain`, and `syscall` are not three peer families. A stack overflow is an entry primitive; ROP is a control technique; SROP/ret2syscall is commonly implemented using ROP gadgets. Real exploits compose them.

That hidden mismatch is visible in the route signals: they are all x86-64 ROP inventory (`pop rdi`, `pop rax`, `syscall`, `/bin/sh`). [`plan:108`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/docs/plans/2026-09-23-walkthrough-engine.md:108>) A singular `family`, singular primary route, linear steps, and one final string encode “pick one technique,” not “compose capabilities.” [`model.py:339`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:339>)

A linear nominal walkthrough is fine. The static-fact execution model is not:

- Format strings frequently discover stack indices, PIE bases, canaries, and libc bases at runtime.
- Heap exploitation is stateful, often cyclic, and depends on allocator transitions.
- Integer/data-only bugs may not crash, have an instruction-pointer offset, or end in a shell.
- Format-string-to-leak-to-ROP spans multiple supposed “families.”

The model itself does not require a cyclic step, but the shared builders and all validation targets strongly bake in crash → offset → gadget → shell. [`plan:64`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/docs/plans/2026-09-23-walkthrough-engine.md:64>) It has not demonstrated that future families “slot in cleanly.”

5. **(f) The plan confuses presentation with exploitation capability.**

The biggest underestimated risk is that this is a renderer being asked to solve cases the exploit engine could not solve, while changing exploitation mechanisms is explicitly out of scope. [`plan:20`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/docs/plans/2026-09-23-walkthrough-engine.md:20>) Converting the automation’s blockers into named unknowns does not produce a complete exploit.

The validation set hides this contradiction: it uses three pre-solved, hand-understood binaries, all with offset 72, and the plan already records the exact required chains. [`plan:193`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/docs/plans/2026-09-23-walkthrough-engine.md:193>) That tests whether known answers can be rendered, not whether a genuinely failed autopwn can become a working walkthrough.

## Low

9. **(e) It is over-engineered in prose metadata and under-engineered in executable state.**

There are numerous narrative containers, but no typed runtime output, parser, state store, branch predicate, timeout, prerequisite, or success oracle. `consumes`/`produces` merely cross-check names; they do not verify that code reads or computes them. [`model.py:265`](</srv/share/dev/supwngo/.claude/worktrees/agent-a94bf3ef2466a61db/supwngo/exploit/walkthrough/model.py:265>) The result is ceremony that creates confidence without enforcing behavior.

Minimum approval bar: make unknowns lazy, make resolver steps return and persist typed values, require the final exploit to consume that runtime state, separate rejected-route explanations from symptom-driven alternatives, and test in a clean environment against at least one genuinely unresolved/failed-autopwn case—not only three fixtures whose complete solutions are already known.
