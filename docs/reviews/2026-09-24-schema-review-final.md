1. **BLOCKING — Merge precedence is incomplete and treats provenance as authority.** The table defines only four of sixteen provenance pairings and omits `derived`/`derived`, `derived`/`measured`, `measured`/`derived`, `asserted`/`asserted`, and incoming `asserted` cases ([plan](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:135)). “Asserted wins” is dangerous: a typo or stale human claim would remain operational despite contradictory evidence. The remote/local example is an applicability-scope difference, not a precedence rule. **Fix:** define the complete matrix; separate provenance from explicit authority; make contradictory values unresolved and unusable until an audited resolution selects one. An assertion should override only when explicitly pinned to the relevant target/environment, not merely because its provenance is `asserted`.

2. **BLOCKING — There is no dependency or staleness model for derived facts.** `ExploitContext.add_leak()` can derive `libc.base` from a leak and libc symbol offset ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:311)), but the proposed schema cannot express that dependency. Superseding the leak could therefore leave a stale base active. Likewise, two conflicting derived facts have no safe winner, and related facts can be merged into an impossible combination. **Fix:** give every observation/fact an immutable ID; add `depends_on`, subject/scope, status, and derivation inputs; recursively invalidate dependents when an input is superseded. Introduce atomic evidence bundles/snapshots so a libc base, leak, libc build identity, and symbol offset are accepted or rejected together. Conflicting derived candidates should remain candidates unless their dependency graphs establish supersession.

3. **BLOCKING — A single document-level binary hash is the wrong applicability invariant.** Exact SHA-256 is correct for layout-dependent addresses, and a byte-for-byte local copy will still match. But remote targets may be represented by a rebuilt or stripped surrogate, while some facts are ABI-, source-, libc-, or session-specific. Conversely, `--context-mismatch=allow` disables protection for every fact and makes unsafe addresses look usable ([plan](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:93)). **Fix:** model artifacts and execution targets separately. Give each fact an applicability scope such as `exact-build`, `build-family/ABI`, `endpoint`, or `process-run`, referencing binary/libc build IDs and hashes as appropriate. Quarantine exact-build facts on mismatch while retaining genuinely portable facts. For an unknown remote build, require an explicit target binding or selective fact import—not a blanket allow switch.

4. **BLOCKING — The design creates multiple sources of truth.** Operational values would exist simultaneously in `facts`, domain `blocks`, and `ExploitContext`: protections, libc, leaks, gadgets, and attempts all overlap. The current class already has two distinct return offsets ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:245)). It also lacks provenance, history, artifacts, arbitrary blocks, conflicts, and superseded records, so it cannot be the lossless in-memory form claimed by the plan ([plan](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:27)). **Fix:** introduce a `ContextDocument` aggregate as the lossless model. Make authoritative facts the sole source of operational values; blocks should contain raw/domain results and references to facts, not duplicate writable values. `ExploitContext` should be a typed projection consumed by exploit code and should emit a change set back into the document.

5. **BLOCKING — Byte-identical `doc → ExploitContext → doc` is not achievable as specified.** Exact bytes include whitespace and key order, which a model does not preserve. More importantly, `ExploitContext` contains `Path`, `bytes`, sets, tuples, `Enum(auto())`, and `Any` fields ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:180)). Existing serializers are already lossy: `AttemptRecord.to_dict()` drops payload bytes and stringifies arbitrary objects ([contracts.py](/srv/share/dev/supwngo/supwngo/exploit/pipeline/contracts.py:96)), while `Protections.to_dict()` omits `rpath` and `runpath` ([binary.py](/srv/share/dev/supwngo/supwngo/core/binary.py:61)). `default=str` cannot be decoded reliably and set strings are not canonical. **Fix:** replace this criterion with two tests: semantic model round-trip and canonical-JSON idempotence. Define explicit stable codecs—enum names, sorted arrays for sets, structured tuples, base64/hex bytes, normalized path strings, and tagged unions for polymorphic fields—and prohibit `default=str`. Preserve unknown document fields in the document model.

6. **BLOCKING — “All 31 commands via one decorator” does not fit the actual CLI.** `batch` operates on a directory containing many binaries ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:920)); `diff` has two binaries ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:1691)); `source` accepts source files or trees ([cli.py](/srv/share/dev/supwngo/supwngo/cli.py:1169)); `libc-id` and `onegadget` concern libc rather than a target binary; `version` and `cyclic*` are targetless. Existing callbacks also print or write results directly rather than returning a shared typed result. A decorator can add an option, but cannot infer subjects or adapt command-local state. The example `fuzz-corpus --auto` command does not exist; the CLI has `fuzz` with different arguments. **Fix:** create a command-capability registry declaring subject cardinality, accepted inputs, consumed blocks, and output adapter. Add collection/multi-artifact subjects, and mark targetless utilities explicitly context-inapplicable. Refactor producing callbacks to return typed results to a central writer. Conformance should test each declared capability, not require every command to emit a single-target document.

7. **MAJOR — Runtime facts are not scoped to a process or session.** ASLR-dependent libc bases, canaries, heap state, and many leaks can expire when a process restarts even when `target.sha256` remains unchanged. The existing architecture explicitly describes `ExploitContext` as a target/session abstraction ([contracts.py](/srv/share/dev/supwngo/supwngo/exploit/pipeline/contracts.py:14)), but the proposed portable document treats all facts alike. **Fix:** require fact scope and lifetime metadata such as `build`, `endpoint`, `boot`, `process`, or `attempt`, plus a run/session identifier and invalidation conditions. Consumers must reject expired runtime facts by default.

8. **MAJOR — Missing/unknown values will silently become invented facts.** `ExploitContext` defaults to amd64/64-bit, default protections, `ASLR=True`, and numerous zero sentinels ([context.py](/srv/share/dev/supwngo/supwngo/core/context.py:187)). Loading the proposed “minimal” hand-authored document and serializing the context could emit these defaults as though they were observed. Zero also ambiguously means unknown or a real value. **Fix:** use optional/presence-tracked fields in the document projection; distinguish absent, unknown, and known-zero; never emit a fact merely because a dataclass supplied a default. Add tests proving a minimal document does not gain phantom facts.

9. **MAJOR — The test and operational plan omit the behaviors most likely to fail.** Schema-valid output does not prove a command actually consumes or honors facts. There are no tests for dependency invalidation, coherent bundles, runtime expiry, same-value evidence merging, conflict resolution, multi-target commands, unknown-field preservation, interrupted writes, or concurrent writers. Artifact paths are called portable despite being plain paths, with no base-resolution or digest-verification rule. YAML loader safety, document size limits, and redaction of payloads, captured flags, remote endpoints, and command material are also unspecified. **Fix:** add consumer contract tests showing facts alter command behavior; property tests for every merge pairing and dependency invalidation; atomic temp-file-plus-rename writes with locking; version migration and extension rules; relative artifact URIs with mandatory digest verification; safe YAML loading and resource limits; and explicit secret/redaction policy.

10. **MINOR — The compatibility story contradicts the dedicated-output design.** A new `--context-out` can coexist with existing `--json`, so it need not cause the claimed breaking output-shape change ([plan](/srv/share/dev/supwngo/docs/plans/2026-09-24-standardized-context-schema.md:49)). Introducing `--legacy-json` only for selectively documented commands leaves other consumers exposed and doubles the migration surface. **Fix:** keep current `--json` and `-o` formats unchanged in v1, make `--context-out` purely additive, and schedule any stdout-format migration separately with a complete deprecation inventory.
