3. **BLOCKING — Plan `classify_slots`: canary classification is not sound.** Increasing stack positional indices read increasing addresses once past the register arguments. Because x86-64 stacks grow downward, the current/innermost frame’s canary is normally at a lower address—and therefore lower index—than callers’ canaries. Thus “lowest” is correct only among values already proven to be frame canaries. Volatile, low-byte-zero, non-small, non-`2^40..2^48` values can instead be aligned non-pointer data or LA57 userspace pointers above `2^48`. On target 05, the stronger evidence is the frame tuple at slots 25–27 and the same guard repeated at slot 29. Fix: require `candidate, plausible saved-RBP, executable return-address` adjacency, preferably corroborated by a repeated guard and disassembly; use process mappings/canonical-address checks rather than the fixed pointer band. Add lower-index decoy and LA57-pointer tests.
